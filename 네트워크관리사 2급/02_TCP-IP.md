## 1. IP 주소 체계

### IPv4 기본
- 길이: **32비트** (4옥텟 × 8비트)
- 표기: 점 10진수 (Dotted Decimal) — `192.168.1.1`
- 구성: **네트워크 ID + 호스트 ID**

### 클래스별 구분 (암기 ★★★)
| 클래스 | 첫 비트 | 첫 옥텟 범위 | 기본 마스크 | 구조 | 네트워크 수 | 호스트 수 |
|---|---|---|---|---|---|---|
| **A** | 0 | **1 ~ 126** | 255.0.0.0 (/8) | N.H.H.H | 126 | 16,777,214 |
| **B** | 10 | **128 ~ 191** | 255.255.0.0 (/16) | N.N.H.H | 16,384 | 65,534 |
| **C** | 110 | **192 ~ 223** | 255.255.255.0 (/24) | N.N.N.H | 2,097,152 | **254** |
| **D** | 1110 | **224 ~ 239** | - | **멀티캐스트** | - | - |
| **E** | 1111 | **240 ~ 255** | - | 연구·예약 | - | - |

> 127로 시작하는 대역은 **루프백** 전용이라 A클래스 호스트 범위에서 제외됩니다.

### 호스트 수 계산 공식 ★
```
사용 가능한 호스트 수 = 2^(호스트 비트 수) - 2
```
**-2 하는 이유**: 네트워크 주소(호스트 비트 전부 0)와 브로드캐스트 주소(전부 1)를 제외

| 호스트 비트 | 전체 | 사용 가능 |
|---|---|---|
| 2 | 4 | **2** |
| 3 | 8 | **6** |
| 4 | 16 | **14** |
| 5 | 32 | **30** |
| 6 | 64 | **62** |
| 7 | 128 | **126** |
| 8 | 256 | **254** |

### 특수 주소 (출제 단골)
| 주소 | 의미 |
|---|---|
| `127.0.0.0/8` | **루프백** (자기 자신). 대표 `127.0.0.1` |
| `0.0.0.0` | 모든 주소 / 기본 라우트 |
| `255.255.255.255` | **제한적 브로드캐스트** (라우터를 넘지 않음) |
| `x.x.x.0` (호스트 비트 0) | **네트워크 주소** |
| `x.x.x.255` (호스트 비트 1) | **직접 브로드캐스트 주소** |
| `169.254.0.0/16` | **APIPA / Link-local** — DHCP 실패 시 자동 할당 |
| `224.0.0.0/4` | 멀티캐스트 |

### 사설 IP (RFC 1918) — 반드시 암기 ★
| 클래스 | 범위 | CIDR |
|---|---|---|
| A | 10.0.0.0 ~ 10.255.255.255 | 10.0.0.0/8 |
| B | 172.16.0.0 ~ **172.31**.255.255 | 172.16.0.0/12 |
| C | 192.168.0.0 ~ 192.168.255.255 | 192.168.0.0/16 |

> ⚠️ **172.32.x.x는 사설 IP가 아닙니다.** 172.16~172.31까지만. 매우 자주 출제됩니다.

### 유니캐스트 / 브로드캐스트 / 멀티캐스트 / 애니캐스트
| 방식 | 설명 |
|---|---|
| **유니캐스트** | 1 : 1 |
| **브로드캐스트** | 1 : 전체 (IPv4에만 존재) |
| **멀티캐스트** | 1 : 그룹 (D클래스 224.x.x.x) |
| **애니캐스트** | 1 : 가장 가까운 하나 (**IPv6에서 도입**) |

> IPv6에는 **브로드캐스트가 없고** 대신 멀티캐스트/애니캐스트를 사용합니다. 시험 단골.

## 2. IP 헤더 구조

### IPv4 헤더 (최소 20바이트, 최대 60바이트)
| 필드 | 크기 | 설명 |
|---|---|---|
| Version | 4bit | 버전(4) |
| IHL (헤더 길이) | 4bit | 4바이트 단위 |
| **TOS / DSCP** | 8bit | 서비스 품질(QoS) |
| Total Length | 16bit | 전체 길이 (최대 65,535) |
| Identification | 16bit | 단편화 식별자 |
| Flags | 3bit | DF(단편화 금지), MF(더 있음) |
| Fragment Offset | 13bit | 단편 위치 |
| **TTL** | **8bit** | **최대 255. 라우터를 지날 때마다 1씩 감소, 0이 되면 폐기** |
| **Protocol** | 8bit | 상위 프로토콜 (**1=ICMP, 6=TCP, 17=UDP**) |
| Header Checksum | 16bit | 헤더 오류 검사 |
| **Source IP** | 32bit | 출발지 |
| **Destination IP** | 32bit | 목적지 |
| Options + Padding | 가변 | 최대 40바이트 |

### 프로토콜 번호 (암기 ★)
| 번호 | 프로토콜 |
|---|---|
| **1** | **ICMP** |
| 2 | IGMP |
| **6** | **TCP** |
| **17** | **UDP** |
| 41 | IPv6 |
| 89 | OSPF |

### TTL의 역할
루프(순환) 방지. 라우터 통과 시 1씩 감소하고 0이 되면 패킷 폐기 + ICMP Time Exceeded 전송.
→ **`traceroute`/`tracert`가 이 원리를 이용**합니다.

## 3. IPv6

| 항목 | 내용 |
|---|---|
| 주소 길이 | **128비트** (IPv4의 4배) |
| 표기 | 16진수 8그룹, **콜론(:) 구분** — `2001:0db8:0000:0000:0000:ff00:0042:8329` |
| 축약 | 앞의 0 생략, 연속된 0 그룹은 `::` 로 한 번만 축약 → `2001:db8::ff00:42:8329` |
| 헤더 | **40바이트 고정** (IPv4는 가변) |
| 헤더 필드 수 | 8개 (IPv4는 13개) — 단순화 |
| 체크섬 | **없음** (상위 계층에 위임) |
| 단편화 | **송신 측에서만** 수행 (라우터는 안 함) |
| 브로드캐스트 | **없음** → 멀티캐스트/애니캐스트로 대체 |
| 보안 | **IPSec 기본 내장** |
| 자동 설정 | **Stateless Auto-configuration (SLAAC)** 지원 |
| QoS | Flow Label 필드로 지원 |

### IPv6 기본 헤더 필드 (2026-2회 5번)
| 필드 | 크기 | 설명 |
|---|---|---|
| Version | 4bit | 6 |
| Traffic Class | 8bit | 우선순위·QoS (IPv4의 TOS 대응) |
| Flow Label | 20bit | 같은 흐름(Flow) 식별 |
| Payload Length | 16bit | 페이로드 길이 |
| Next Header | 8bit | 다음 헤더·상위 프로토콜 (IPv4의 Protocol 대응) |
| **Hop Limit** | 8bit | **데이터그램의 생존 기간** — 라우터마다 1 감소, 0이면 폐기 (IPv4의 TTL 대응) |
| Source / Destination Address | 각 128bit | 출발지 / 목적지 주소 |

> 합계 = 4+8+20+16+8+8+128+128 = 320비트 = **40바이트 고정**. 체크섬 필드는 **없습니다.**

### IPv6 텍스트 표기 규칙 (RFC 5952) — 2026-3회 15번
| 규칙 | 내용 | 예 |
|---|---|---|
| **선행 0 생략** | 각 16비트 필드의 앞쪽 0은 **반드시 생략** (생략할 수 없다는 보기는 ✗) | `2001:0db8:0001` → `2001:db8:1` |
| 값이 모두 0인 필드 | `0000`이 아니라 **`0`** 으로 표기 | `2001:db8:0:1:1:1:1:1` |
| **`::` 사용 조건** | **연속된 0 필드가 2개 이상**일 때만 사용 | `2001:db8::1` |
| `::`은 **한 번만** | 한 주소에서 여러 번 쓸 수 없음 (여러 번 가능하다는 보기는 ✗) | |
| 0 구간이 여러 개 | **가장 긴 구간**을 `::`으로 줄임 | `2001:0:0:1:0:0:0:1` → `2001:0:0:1::1` |
| 길이가 같은 구간이 여러 개 | **가장 왼쪽(처음)** 구간을 `::`으로 줄임 (오른쪽이 아님) | `2001:db8:0:0:1:0:0:1` → `2001:db8::1:0:0:1` |
| 0 필드가 **하나뿐** | `::`으로 **줄이지 않고** `0`으로 표기 | `2001:db8:0:1:1:1:1:1` |
| 영문자 | **소문자** | `2001:DB8::1` → `2001:db8::1` |

> 기출 15번 보기 판정: ① 선행 0 생략 불가(✗) ② `::` 여러 번 사용(✗) ③ 가장 오른쪽 구간 축약(✗, 왼쪽) ④ 0 필드가 하나뿐이면 `0`으로 표기(**○ 정답**)

### IPv6 주소 종류
| 종류 | 접두사 | 설명 |
|---|---|---|
| **글로벌 유니캐스트** | `2000::/3` | 공인 주소 |
| **링크 로컬** | **`FE80::/10`** | 같은 링크 내에서만 유효 (자동 생성) |
| **유니크 로컬** | `FC00::/7` | 사설 주소 (IPv4 사설IP 대응) |
| **멀티캐스트** | **`FF00::/8`** | 그룹 통신 |
| 루프백 | `::1` | IPv4의 127.0.0.1 대응 |
| 미지정 | `::` | 0.0.0.0 대응 |

### IPv4 → IPv6 전환 기술 (출제 포인트)
| 기술 | 설명 |
|---|---|
| **듀얼 스택(Dual Stack)** | 두 프로토콜 동시 지원 |
| **터널링(Tunneling)** | IPv6 패킷을 IPv4로 캡슐화해 전달 |
| **주소 변환(NAT-PT / Translation)** | IPv6 ↔ IPv4 헤더 변환 |

> **NAT64**: IPv6 클라이언트 ↔ IPv4 서버 변환(보통 DNS64와 함께 사용). **NAT44**는 IPv4 사설↔공인 주소 변환일 뿐 **IPv4/IPv6 전환 기술이 아닙니다** (2026-3회 14번 정답).

## 4. ARP / RARP

| 프로토콜 | 기능 |
|---|---|
| **ARP** (Address Resolution Protocol) | **IP 주소 → MAC 주소** 변환 |
| **RARP** (Reverse ARP) | **MAC 주소 → IP 주소** 변환 (디스크리스 워크스테이션) |
| **Proxy ARP** | 라우터가 다른 네트워크 호스트를 대신해 응답 |
| **Gratuitous ARP** | 자기 IP에 대해 ARP 요청 → IP 충돌 감지, 캐시 갱신 |

### ARP 동작 과정
```
1. ARP Request  — 브로드캐스트로 "이 IP의 MAC은?" 질의
2. ARP Reply    — 해당 호스트가 유니캐스트로 자기 MAC 응답
3. ARP 캐시에 저장 (일정 시간 유지)
```

```bash
arp -a              # ARP 캐시 확인 (윈도우/리눅스 공통)
arp -d 192.168.1.1  # 항목 삭제
arp -s IP MAC       # 정적 등록
```

> **ARP Request는 브로드캐스트, ARP Reply는 유니캐스트** — 시험 단골

## 5. ICMP / IGMP

### ICMP (Internet Control Message Protocol)
IP의 **오류 보고 및 진단** 메시지 전달. **프로토콜 번호 1**.
`ping`과 `traceroute`가 사용.

#### 주요 ICMP 메시지 타입 (암기 ★)
| 타입 | 이름 | 의미 |
|---|---|---|
| **0** | **Echo Reply** | ping 응답 |
| **3** | **Destination Unreachable** | 목적지 도달 불가 |
| 4 | Source Quench | 혼잡 알림(폐기됨) |
| 5 | Redirect | 더 나은 경로 안내 |
| **8** | **Echo Request** | ping 요청 |
| **11** | **Time Exceeded** | TTL 초과 (traceroute가 이용) |
| 12 | Parameter Problem | 헤더 오류 |
| 13/14 | Timestamp Request/Reply | 시간 동기 |
| 17/18 | **Address Mask Request/Reply** | 서브넷 마스크 질의·응답 (2026-3회 7번 보기에 등장) |

> 함정: **8 = 요청(Request), 0 = 응답(Reply)** 순서가 뒤집혀 있습니다.

### ICMP 메시지 분류 (2026-1회 5번)
| 구분 | 설명 | 예 |
|---|---|---|
| **오류 보고 메시지** | IP 데이터그램을 처리하다 생긴 **오류를 송신자에게 알림** | Destination Unreachable(3), Time Exceeded(11), Parameter Problem(12), Redirect(5) |
| **질의(Query) 메시지** | 호스트·라우터 사이의 **요청/응답 쌍** | Echo Request/Reply(8/0), Timestamp(13/14), Address Mask(17/18) |

- ICMP는 IP의 비신뢰성을 보완해 **오류·상태를 보고**하는 3계층 프로토콜입니다. 오류를 **보고할 뿐 복구하지는 않습니다.**
- **TTL은 ICMP가 아니라 IP 헤더의 필드**입니다. ICMP가 ‘TTL을 제공한다’는 설명은 틀린 설명입니다(1회 5번 정답).
- ping은 Echo 질의 메시지(반향/회답)로 호스트 간 도달 가능성을 확인합니다.

### traceroute / tracert 동작 (2급 단답형 출제)
| 구분 | 리눅스 `traceroute` | 윈도우 `tracert` |
|---|---|---|
| 기본 탐색 패킷 | **UDP** (옵션 `-I`로 ICMP 가능) | **ICMP Echo Request** |
| 원리 | **TTL을 1부터 1씩 증가**시키며 전송 → TTL이 0이 된 중간 라우터가 **ICMP Time Exceeded(11)** 로 응답 → 라우터 주소 수집 | 동일 |
| 목적지 도달 신호 | 목적지가 **ICMP Port Unreachable** 로 응답(UDP 사용 시) | ICMP **Echo Reply** |


### IGMP (Internet Group Management Protocol)
**멀티캐스트 그룹 관리**. 호스트가 멀티캐스트 그룹에 가입·탈퇴할 때 사용. 프로토콜 번호 2.

## 6. TCP와 UDP

| 구분 | TCP | UDP |
|---|---|---|
| 연결 방식 | **연결형** | **비연결형** |
| 신뢰성 | 높음(ACK, 재전송) | 낮음 |
| 순서 보장 | 보장 | 미보장 |
| 흐름 제어 | 슬라이딩 윈도우 | 없음 |
| 혼잡 제어 | 있음 | 없음 |
| 헤더 크기 | **20~60바이트** | **8바이트 고정** |
| 전송 단위 | 세그먼트 | 데이터그램 |
| 속도 | 느림 | 빠름 |
| 프로토콜 번호 | **6** | **17** |
| 용도 | HTTP, FTP, SMTP, Telnet, SSH, POP3 | DNS, DHCP, TFTP, SNMP, NTP, VoIP, 스트리밍 |

### TCP 헤더 주요 필드
| 필드 | 크기 | 설명 |
|---|---|---|
| Source Port / Destination Port | 각 16bit | 포트 번호 |
| **Sequence Number** | 32bit | 순서 번호 |
| **Acknowledgment Number** | 32bit | 확인 응답 번호 |
| Header Length | 4bit | |
| **Flags** | 6bit(기본) / **9bit**(현재 정의: NS·CWR·ECE 추가) | URG, ACK, PSH, RST, SYN, FIN (+ NS, CWR, ECE) |
| **Window Size** | 16bit | 수신 가능 버퍼 크기(흐름 제어) |
| Checksum | 16bit | |
| Urgent Pointer | 16bit | |

> 필드 길이 기출(2026-2회 12번): Source port **16비트** · Sequence Number **32비트** · Flags **9비트(현재 정의)** · **Checksum은 32비트가 아니라 16비트**(‘적절하지 않은 것’).

### UDP 헤더 (8바이트 고정) — 2026-3회 6번
| 필드 | 크기 | 설명 |
|---|---|---|
| Source Port | 16bit | 출발지 포트 |
| Destination Port | 16bit | 목적지 포트 |
| Length | 16bit | 헤더 + 데이터 길이 |
| Checksum | 16bit | 오류 검사 (IPv4에서는 선택, **IPv6에서는 필수**) |

> UDP 헤더에는 **순서 번호·확인 응답 번호·윈도우 크기·플래그가 없습니다** (모두 TCP 전용). 기출 6번의 정답: **확인 응답 번호(Acknowledgment Number)** 는 UDP 헤더에 포함되지 않음.

### TCP 플래그 (암기 ★)
| 플래그 | 의미 |
|---|---|
| **URG** | 긴급 데이터 |
| **ACK** | 확인 응답 유효 |
| **PSH** | 버퍼링 없이 즉시 전달 |
| **RST** | 연결 강제 재설정·거부 |
| **SYN** | 연결 요청(동기화) |
| **FIN** | 연결 종료 요청 |

### 3-Way Handshake (연결 수립) ★
```
Client                         Server
  │──── SYN (seq=x) ─────────────▶│      [SYN_SENT]
  │◀─── SYN+ACK (seq=y,ack=x+1) ──│      [SYN_RECEIVED]
  │──── ACK (ack=y+1) ───────────▶│      [ESTABLISHED]
```

### 4-Way Handshake (연결 종료)
```
  │──── FIN ─────────▶│    [FIN_WAIT_1]
  │◀─── ACK ──────────│    [CLOSE_WAIT]
  │◀─── FIN ──────────│    [LAST_ACK]
  │──── ACK ─────────▶│    [TIME_WAIT] → CLOSED
```

### TCP 상태 (netstat 출력에 나옴)
| 상태 | 의미 |
|---|---|
| **LISTEN** | 연결 대기 중 (서버) |
| **SYN_SENT** | 연결 요청 보냄 |
| **SYN_RECV** | 연결 요청 받음 |
| **ESTABLISHED** | 연결 완료 |
| **FIN_WAIT** | 종료 대기 |
| **TIME_WAIT** | 종료 후 일정 시간 대기 |
| **CLOSE_WAIT** | 상대가 종료 요청 |
| **CLOSED** | 연결 종료 |

### SYN Flooding 공격
3-way handshake의 SYN만 대량 전송해 서버의 연결 대기 큐를 고갈시키는 DoS 공격.
대응: SYN Cookie, 큐 크기 증가, 방화벽 임계값 설정

## 8. 응용 계층 프로토콜

- 상태 코드 (출제 포인트)

### FTP
- 제어 21, 데이터 20
- **Active 모드**: 서버(20) → 클라이언트로 데이터 연결. 클라이언트 방화벽에 막히기 쉬움
- **Passive 모드**: 클라이언트 → 서버(임의 포트). 방화벽 환경에 유리

### 메일 프로토콜
| 프로토콜 | 역할 | 포트 |
|---|---|---|
| **SMTP** | **발신(송신)** | 25 |

| **IMAP** | 수신 — **서버에 보관**, 다중 기기 동기화 | 143 |
| MIME | 첨부파일·멀티미디어 인코딩 | - |

### DNS
| 레코드 | 의미 |
|---|---|
| **A** | 도메인 → IPv4 |
| **AAAA** | 도메인 → IPv6 |
| **CNAME** | 별칭 |
| **MX** | 메일 서버 (**우선순위 값이 작을수록 우선**) |
| **NS** | 네임서버 |

| **SOA** | 권한 시작 정보 |
| TXT | 텍스트(SPF 등) |

- **재귀적 질의(Recursive)**: 클라이언트 → 로컬 DNS (최종 답을 책임지고 가져옴)
- **반복적 질의(Iterative)**: 로컬 DNS → 루트 → TLD → 권한 DNS
- 계층: 루트(.) → TLD(.com/.kr) → 2차 도메인 → 호스트

#### DNS TTL(Time To Live) (2026-1회 44번 · 2회 2번)
- 레코드를 **캐시 DNS 서버·클라이언트가 보관해도 되는 시간(초)** = ‘데이터가 DNS 캐시에서 만료되기까지 남은 시간’ (캐싱 주기)
- TTL이 **짧으면**: 변경(예: IP 변경)이 **빨리 반영**되지만 **질의가 잦아져 서버 부하 증가**
- TTL이 **길면**: 캐시 적중이 늘어 **부하·트래픽 감소**, 대신 IP가 바뀌어도 **갱신이 늦어져 불편**
- 레코드에 TTL을 따로 지정하지 않아도 영역의 **기본(최소) TTL(SOA)** 이 적용되어 **정방향 조회는 정상 동작**합니다(‘TTL 미설정 시 조회 불가’는 ✗).
- **IP 헤더의 TTL(남은 홉 수)과는 다른 개념**입니다.

### DHCP — DORA (순서 암기 ★)
```
1. DISCOVER — 클라이언트 브로드캐스트로 서버 탐색
2. OFFER    — 서버가 IP 제안
3. REQUEST  — 클라이언트가 해당 IP 요청
4. ACK      — 서버가 최종 승인
```
- 실패 시 **169.254.x.x (APIPA)** 자동 할당
- 임대 갱신: 50% 시점 RENEW, 87.5% 시점 REBIND
- DHCP Relay Agent: 다른 서브넷의 DHCP 서버로 요청 중계

#### IP 주소 할당 방식 3가지 (2026-3회 17번)
| 방식 | 설명 | 용도 |
|---|---|---|
| **수동 할당(Manual)** | 관리자가 **MAC 주소별로 IP를 지정**(예약). 항상 같은 IP | 서버·프린터 |
| **자동 할당(Automatic)** | 서버가 풀에서 한 번 할당하면 **영구적으로 유지**(반납하지 않음) | 변동이 적은 환경 |
| **동적 할당(Dynamic)** | **임대(Lease) 기간** 동안만 사용, 만료되면 회수해 재사용 | 일반 PC (가장 흔함) |

> **‘우선순위 할당(Priority Allocation)’이라는 방식은 없습니다** (기출 17번 정답).

### SNMP
- 네트워크 장비 관리. **161(폴링), 162(트랩)**
- 구성: **Manager(NMS)**, **Agent**, **MIB**(관리 정보 베이스), **OID**
- 주요 명령: GET, GETNEXT, SET, **TRAP**(에이전트가 능동 보고), INFORM
- 버전: v1(평문 community), v2c, **v3(인증·암호화 지원)**

## 10. 라우팅 프로토콜 (운용기기와 겹침)

> ⚠️ **2급에서는 개념 위주입니다.** RIP/OSPF의 방식·메트릭·최대 홉 비교는 필기·단답형에 나오지만, OSPF·EIGRP·BGP **설정 명령**과 세부 타이머는 1급 성격입니다(→ [12_부록_1급 수준 심화.md](12_부록_1급%20수준%20심화.md)). BGP·EIGRP는 '무엇인가' 한 줄만 알아두면 충분합니다.

### 분류
| 구분 | 종류 |
|---|---|
| **IGP (내부)** | RIP, IGRP, EIGRP, OSPF, IS-IS |
| **EGP (외부)** | **BGP** |

| 방식 | 설명 | 프로토콜 |
|---|---|---|
| **거리 벡터(Distance Vector)** | 인접 라우터와 전체 테이블 교환. 홉 수 기준 | **RIP**, IGRP |
| **링크 상태(Link State)** | 전체 토폴로지 정보 보유, SPF(다익스트라) 계산 | **OSPF**, IS-IS |
| **하이브리드** | 두 방식 결합 | **EIGRP** (Cisco 전용) |
| **경로 벡터** | AS 경로 기반 | **BGP** |

> 기출 48번: ‘인접 라우터에 정기적으로 전달 + 벨만-포드 알고리즘’ = **Distance Vector** → 해당 프로토콜은 **RIP·IGRP**, **해당하지 않는 것은 OSPF**(링크 상태, 다익스트라). BGP는 경로 벡터 방식입니다.

### RIP vs OSPF (출제 단골)
| 구분 | RIP | OSPF |
|---|---|---|
| 방식 | 거리 벡터 | **링크 상태** |
| 메트릭 | **홉 수(Hop Count)** | **Cost (대역폭 기반)** |
| 최대 홉 | **15** (16 = 무한대) | 제한 없음 |
| 갱신 주기 | 30초마다 전체 테이블 | 변경 시에만 |
| 수렴 속도 | 느림 | **빠름** |
| 규모 | 소규모 | **대규모** |
| 알고리즘 | Bellman-Ford | **Dijkstra (SPF)** |
| 버전 | RIPv1(클래스풀), **RIPv2(VLSM 지원)** | OSPFv2(IPv4), v3(IPv6) |

### OSPF 특징 (2026-2회 13번)
- **링크 상태** 라우팅 프로토콜이며 **AS(자율 시스템) 내부**(IGP)에서 사용
- **Hello 패킷**으로 이웃 라우터를 발견하고 정상 동작(생존)을 확인
- **비용(Cost)이 같은 여러 경로를 동시에 사용(ECMP)** 할 수 있음 — ‘가장 낮은 비용의 단일 경로만 사용하고 다른 경로는 배제’는 ✗
- 계층적 설계: **Area**로 구분(백본 Area 0), 변경이 있을 때 **LSA**를 전파
- 버전: **OSPFv2(IPv4)**, **OSPFv3(IPv6)** — IP 버전에 따라 OSPF 버전이 다름
- IP 프로토콜 번호 **89**

### 정적 vs 동적 라우팅
| 구분 | 정적(Static) | 동적(Dynamic) |
|---|---|---|
| 설정 | 관리자 수동 | 프로토콜 자동 |
| 오버헤드 | 없음 | 있음(대역폭·CPU) |
| 장애 대응 | 수동 변경 필요 | **자동 우회** |
| 적합 규모 | 소규모 | 중·대규모 |

16. netstat에서 서버가 대기 중인 상태 표시? → **LISTEN**
17. HTTP 404와 500의 의미? → **Not Found / Internal Server Error**

21. SNMP 폴링/트랩 포트? → **161 / 162**
22. 가정용 공유기가 사용하는 NAT 방식? → **PAT (NAPT)**
23. RIP의 최대 홉 수와 메트릭? → **15홉, 홉 카운트**
24. OSPF의 알고리즘과 메트릭? → **다익스트라(SPF), Cost**
25. 외부 AS 간 라우팅 프로토콜? → **BGP**
