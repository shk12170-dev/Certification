## 1. 윈도우 서버 실기 8대 영역 (후기 기준)

| # | 영역 | 단골 작업 |
|---|---|---|
| ① | **네트워크 설정(IP)** | IP·서브넷·게이트웨이·DNS 입력, 2진수↔10진수 변환, 첫/마지막 사용 가능 IP 계산 |
| ② | **DNS** | 정방향 조회 영역(주 영역) 생성, **SOA 값 입력**, **A·CNAME 레코드** 추가 |
| ③ | **DHCP** | 새 범위 생성(이름·주소 범위·제외·임대 기간), **예약**, 활성화 |
| ④ | **FTP** | FTP 사이트 추가(경로·IP·포트), 권한, IP 거부, 최대 연결 수, 접속 메시지 |
| ⑤ | **IIS(웹)** | 웹 사이트 추가(포트 8080 등), IP 제한, 기본 문서, 연결 제한, 바인딩 |
| ⑥ | **사용자·그룹** | 계정 생성, 암호 옵션, 그룹 가입, 홈 폴더 |
| ⑦ | **로컬 보안 정책** | 암호 복잡성·사용 기간, 계정 잠금 임계값·기간 |
| ⑧ | **서비스** | 시작 유형 변경(사용 안 함/자동), 서비스 중지·시작 |

> 문제 형식은 **같은 주제의 1번/2번 변형**이 반복되는 경우가 많습니다. 즉 위 8개 영역을 손에 익히면 점수가 나옵니다.

### 공통 요령
- **지시되지 않은 항목은 건드리지 않고 "다음"으로 넘깁니다.** (예: DHCP 마법사의 라우터·DNS 옵션, FTP 인증 설정)
- 마지막에 **활성화**를 요구하지 않으면 활성화하지 않습니다. 요구하면 반드시 합니다.
- 문제의 **이름·경로·포트·IP**는 대소문자와 철자 그대로 입력합니다.
- 생소한 서비스가 목록에 보이면 다른 것을 잘못 건드렸을 가능성이 큽니다.

## 2. ① 네트워크 설정 (IP 입력 + 계산)

### 설정 경로
```
네트워크 및 공유 센터 → 어댑터 설정 변경 → 이더넷 우클릭 → 속성
→ 인터넷 프로토콜 버전 4(TCP/IPv4) → 속성
   · 다음 IP 주소 사용: IP 주소 / 서브넷 마스크 / 기본 게이트웨이
   · 다음 DNS 서버 주소 사용: 기본 설정 DNS 서버
→ 고급: 게이트웨이 추가, DNS 추가
```
(실행 창 명령: `ncpa.cpl`)

### 계산형 문제 (실기 단골)
- **2진수 IP → 10진수**: `11000000.10101000.01100100.00001010` → **192.168.100.10**
- **프리픽스 → 마스크**: /22 → `255.255.252.0`
- **첫 사용 가능 IP = 네트워크 주소 + 1**, **마지막 사용 가능 IP = 브로드캐스트 − 1**
- **필요 호스트 수 → 프리픽스**: 호스트 6개 → 2³−2 = 6 → **/29**

> 계산 연습은 [03_서브네팅 완전정복.md](03_서브네팅%20완전정복.md) 「실기 계산 유형」에서 하세요.

## 3. ② DNS 서버 (DNS 관리자)

### 정방향 조회 영역 만들기
```
DNS 관리자(dnsmgmt.msc) → 서버 → 정방향 조회 영역 → 우클릭 → 새 영역
→ 영역 종류: 주 영역(Primary zone)
→ 영역 이름: example.com   (문제에서 준 이름 그대로)
→ 영역 파일: 새 파일 만들기(기본값)
→ 동적 업데이트: 문제 지시 없으면 기본값 → 마침
```

### SOA 레코드 수정
```
영역 우클릭 → 속성 → 「시작 권한(SOA)」 탭
 · 일련 번호(Serial)        : 문제에서 준 값을 그대로
 · 주 서버(Primary server)  : 문제에서 준 FQDN
 · 책임자(Responsible person): 문제에서 준 값 (예: admin.example.com.)
 · 새로 고침 간격(Refresh)
 · 다시 시도 간격(Retry)
 · 만료 기간(Expire)
 · 최소(기본) TTL
```

| SOA 필드 | 의미 |
|---|---|
| Serial | 영역 데이터 **버전 번호**(보조 DNS가 비교) |
| Refresh | 보조 DNS가 주 DNS에 **갱신 확인하는 주기** |
| Retry | 갱신 실패 시 **재시도 간격** |
| Expire | 주 서버와 연결이 끊긴 보조 서버가 **영역 데이터를 유효로 인정하는 기간** |
| Minimum TTL | 캐시 유지 시간(**네거티브 캐시** 기준) |

### 레코드 추가
```
영역 우클릭 →
 · 새 호스트(A 또는 AAAA)  : 이름 www, IP 주소 192.168.1.10
 · 새 별칭(CNAME)          : 별칭 이름 web, 대상 호스트 www.example.com
 · 새 메일 교환기(MX)       : 메일 서버 FQDN, 우선 순위(작을수록 우선)
```

> **영역 이름은 마침표(.)로 끝나는 FQDN**으로 입력하는 항목이 있으니 에뮬레이터의 안내문을 보세요.

## 4. ③ DHCP 서버

### 새 범위(Scope) 만들기
```
DHCP 관리자(dhcpmgmt.msc) → IPv4 → 우클릭 → 새 범위
 1) 범위 이름 / 설명
 2) IP 주소 범위: 시작 IP / 끝 IP / 서브넷 마스크(길이)
 3) 제외 추가: 제외할 주소 범위(시작~끝) 입력 후 「추가」
 4) 임대 기간: 일/시간/분
 5) DHCP 옵션 구성: 문제에 지시가 없으면 「아니요, 나중에 구성」 또는 건너뜀
 6) 이 범위 활성화: 문제가 요구할 때만 「예」
```

### 예약(Reservation)
```
범위 → 예약 → 우클릭 → 새 예약
 · 예약 이름 / IP 주소 / MAC 주소(하이픈 없이 입력하는 경우 많음) / 설명
```
> 예약은 **특정 MAC에 항상 같은 IP**를 주는 기능입니다.

### 주요 개념
| 용어 | 의미 |
|---|---|
| 범위(Scope) | 분배할 IP 풀 |
| **제외 범위** | 풀 안에서 **분배하지 않을 주소**(서버·프린터 등 고정 IP용) |
| 임대 기간 | 할당 주소 사용 기간 (기본 8일) |
| **예약** | MAC ↔ IP 고정 매핑 |
| 옵션 | 라우터(003), DNS 서버(006), 도메인 이름(015) |
| **권한 부여(Authorize)** | AD 환경에서 DHCP 서버를 승인 (비인가 서버 차단) |

### 필기 포인트: Windows Server 2022 DHCP (2026-3회 32번)
3회 필기 32번은 Windows Server 2022 DHCP 구성 설명을 물었고, 공식 정답표는 **④와 ①을 복수 정답**으로 표기했습니다.

| 항목 | 내용 |
|---|---|
| 새 범위 마법사 순서 | 범위 이름 → IP 주소 범위 → **제외 주소·지연** → 임대 기간 → DHCP 옵션 구성 → 범위 활성화 |
| **지연(Subnet delay)** | 제외 단계에서 지정. 서버가 응답을 **지연시키는 시간(밀리초, ms)** — 여러 DHCP 서버(분산·보조) 구성 시 우선순위 조절에 사용 → **기출 정답 ④** |
| 임대 기간 | 마법사에서 일·시간·분으로 설정. 기출에서는 ‘일·시간·분·초 단위’ 보기(①)도 정답 표기됨(복수 정답) — **초 단위 지원 여부는 서버/에뮬레이터에서 직접 확인** |
| WINS 서버 | ‘더 이상 구성하지 않는다’는 보기(②)는 정답표에서 **오답 처리** — 옵션 단계에 WINS 항목이 남아 있는 것으로 보임(정답표 기준 추정) |
| 예약 지원 유형 | **DHCP / BOOTP / 둘 다** 중 선택 가능 → ‘BOOTP 없이 DHCP만 가능’(③)은 **오답** |

> 이 문항은 복수 정답이므로 암기보다 **마법사를 직접 한 번 따라가 보는 것**이 안전합니다. (실기 에뮬레이터에서 새 범위 만들기 연습과 같은 작업)

### DHCP Failover(장애 조치)와 MCLT (2026-2회 42번)
**두 DHCP 서버가 임대 정보를 동기화**해, 한 서버에 장애가 나거나 서버 간 통신이 끊겨도 다른 서버가 서비스를 이어 가는 기능입니다.

| 항목 | 내용 |
|---|---|
| 모드 | **Load Balance**(두 서버가 요청을 나눠 처리, 기본 50:50) / **Hot Standby**(활성 서버 + 대기 서버) |
| **MCLT** (Maximum Client Lead Time) | **장애 조치 파트너 서버가 기존 임대를 임시로 갱신(연장)해 줄 수 있는 최대 시간** ← 기출 정답 |
| 동기화 | 두 서버가 **임대 정보**를 서로 복제 |
| 통신 포트 | TCP **647** (장애 조치 통신) |
| 설정 단위 | **범위(Scope)** 별로 장애 조치 관계를 구성 |

> 기출 2회 42번 지문: Load Balance Failover 방식의 두 DHCP 서버가 임대 정보를 동기화하고, 한 서버가 끊겨도 다른 서버가 **기존 임대를 임시로 갱신**할 수 있어야 함 → 그 한계 시간이 MCLT.

## 5. ④ FTP 사이트 / ⑤ IIS 웹 사이트 (IIS 관리자)

### 열기
`inetmgr` 또는 서버 관리자 → 도구 → **IIS(인터넷 정보 서비스) 관리자**

### 웹 사이트 추가
```
사이트 우클릭 → 웹 사이트 추가
 · 사이트 이름 / 실제 경로(물리 경로) / 바인딩(종류 http, IP 주소, 포트 8080, 호스트 이름)
```

### FTP 사이트 추가
```
사이트 우클릭 → FTP 사이트 추가
 1) 사이트 이름 / 콘텐츠 디렉터리(실제 경로)
 2) 바인딩: IP 주소, 포트 21, SSL 「SSL 사용 안 함」
 3) 인증 및 권한 부여 정보:
      · 인증: 문제 지시 없으면 건드리지 않음
      · 권한 부여: 모든 사용자 / 지정된 사용자
      · 사용 권한: 읽기 / 쓰기
```

### FTP 사이트 세부 설정 (사이트 선택 → 가운데 기능 아이콘)
| 아이콘 | 설정 내용 |
|---|---|
| **FTP IP 주소 및 도메인 제한** | 특정 IP **거부 항목 추가** (또는 허용) |
| **FTP 메시지** | 배너 메시지(접속 시), 환영 메시지, 종료 메시지, **최대 연결 메시지** |
| **FTP 방화벽 지원** | 수동 모드 포트 범위 |
| **FTP 인증 / 권한 부여 규칙 / 현재 세션** | 인증 방식 / 사용자별 읽기·쓰기 / 접속자 확인 |
| 사이트 **고급 설정 → 연결 → 최대 연결 수** | **동시 접속 수 제한** |

### 웹 사이트 세부 설정
| 설정 | 위치 |
|---|---|
| **IP 주소 및 도메인 제한** | 사이트 선택 → 해당 아이콘 → **허용/거부 항목 추가** → 특정 IP 또는 **IP 주소 범위**(예: 192.168.100.0 / 255.255.255.0) |
| **기본 문서** | 사이트 선택 → 기본 문서 → 필요한 파일만 남기고 나머지 제거, 순서 조정 |
| **연결 제한** | 사이트 우클릭 → 웹 사이트 관리 → 고급 설정 → **연결 제한(제한 시간·최대 동시 연결 수)** |
| **바인딩 편집** | 사이트 우클릭 → **바인딩 편집** → 추가 (같은 IP로 사이트 2개를 운영하려면 **포트 또는 호스트 이름**으로 구분) |
| 디렉터리 검색 | 사이트 → 디렉터리 검색 → 사용/사용 안 함 (홈 디렉터리에 제공할 문서가 없을 때 **폴더·파일 목록을 보여줄지** 지정) |
| **홈 디렉터리(실제 경로)** | 사이트 → 기본 설정 → **실제 경로 변경** — 기본값은 `C:\inetpub\wwwroot`이지만 **반드시 이 경로여야 하는 것은 아님** |
| **가상 디렉터리 추가** | 사이트 우클릭 → 가상 디렉터리 추가 → **별칭(Alias) + 실제 경로** 지정 → 홈 디렉터리 밖의 폴더를 URL로 연결 |
| 로깅 | 사이트 → 로깅 → 로그 위치·형식 |

### IIS 로그 설정 (2026-1회 45번)
| 항목 | 내용 |
|---|---|
| 위치 | 사이트 → **로깅** → 로그 파일 **디렉터리(저장 위치) 변경 가능** (기본 `%SystemDrive%\inetpub\logs\LogFiles`) ← 기출 정답 |
| 형식 | **W3C(기본)**, IIS, NCSA, 사용자 지정 — W3C만 지원하는 것이 아님 |
| 롤오버 | 시간별·매일·매주·매월·**최대 파일 크기**·새 로그 안 만듦 중 선택. 최대 크기에 도달하면 **새 로그 파일을 만들며 이전 로그를 자동 삭제하지 않음** |
| 기록 시점 | 버퍼링 후 기록되므로 **즉시(실시간) 반영되지 않을 수 있음** |

### FTP 서버 설치 (2026-2회 44번)
- GUI: **서버 관리자 → 역할 및 기능 추가 → 서버 역할 → 웹 서버(IIS) → FTP 서버**(역할 서비스) 선택 ← 기출 정답
- PowerShell: `Install-WindowsFeature Web-Ftp-Server -IncludeManagementTools` (PowerShell로도 설치 가능)
- IIS의 FTP는 **FTP/FTPS**를 제공합니다. **SFTP(SSH 기반)는 IIS FTP 기능만으로 구성할 수 없습니다.**
- FTP 서버는 Windows Server의 **기본 역할·기능에 포함**되어 있어 서드파티 소프트웨어가 필수는 아닙니다.

### 웹 서버 핵심 개념
| 개념 | 설명 |
|---|---|
| **바인딩** | (IP, 포트, 호스트 이름) 조합으로 사이트를 구분 |
| 가상 호스트 | 한 서버에서 여러 도메인 운영 (호스트 헤더) |
| 기본 문서 | 디렉터리 접근 시 자동 제공되는 파일(`index.html`, `default.htm`). 추가·삭제·순서 조정 가능 |
| 홈 디렉터리 | 사이트 콘텐츠가 있는 실제 폴더. **임의 경로로 지정 가능** (기본값 `C:\inetpub\wwwroot`) |
| 가상 디렉터리 | **별칭 + 실제 경로**로 다른 위치의 폴더를 사이트 URL 아래에 연결 |
| 디렉터리 검색 | 기본 문서가 없을 때 폴더 내용을 목록으로 보여주는 기능 |
| 포트 | HTTP 80, HTTPS 443, FTP 21(제어)/20(데이터) |

## 7. ⑦ 로컬 보안 정책 (`secpol.msc`)

```
로컬 보안 정책 → 계정 정책
 ├─ 암호 정책
 │    · 암호는 복잡성을 만족해야 함       → 사용 / 사용 안 함
 │    · 최소 암호 길이
 │    · 최소 암호 사용 기간 / 최대 암호 사용 기간  (일)
 │    · 최근 암호 기억
 └─ 계정 잠금 정책
      · 계정 잠금 임계값      → 로그온 실패 허용 횟수 (예: 3회)
      · 계정 잠금 기간        → 잠금 지속 시간 (예: 60분)
      · 다음 시간 후 계정 잠금 수를 원래대로 설정 → 실패 카운터 초기화 시간
```

> **임계값을 먼저 설정**하면 잠금 기간(기본 30분)이 자동으로 함께 제안됩니다. 문제의 값(예: 60분)으로 **반드시 수정**하세요.
> "3회 실패 시 60분 잠금" = 임계값 **3**, 잠금 기간 **60**.

| 정책 | 의미 |
|---|---|
| 암호 복잡성 | 대문자·소문자·숫자·특수문자 중 3종 이상 + 계정명 포함 금지 |
| 최소 암호 사용 기간 | 변경 후 **최소** 이 기간은 변경 불가 |
| 최대 암호 사용 기간 | 이 기간이 지나면 **변경 강제** |
| 계정 잠금 임계값 | 이 횟수 실패 시 잠김 |

## 8. ⑧ 서비스 관리자 (`services.msc`)

```
서비스 → 대상 서비스 우클릭 → 속성
 · 시작 유형: 자동 / 자동(지연된 시작) / 수동 / 사용 안 함
 · 서비스 상태: 시작 / 중지 / 일시 중지 / 다시 시작
 → 적용 → 확인
```

| 작업 예 | 설정 |
|---|---|
| Telnet 서비스 끄기 | 시작 유형 **사용 안 함** + 서비스 상태 **중지** |
| World Wide Web Publishing Service 중지 | 서비스 상태 **중지** (필요 시 시작 유형도 변경) |
| 서비스 켜기 | 시작 유형 **자동** + 서비스 상태 **시작** |

> **시작 유형과 서비스 상태는 별개**입니다. 문제가 "부팅 시 자동으로 시작"이라 하면 시작 유형을 바꾸고, "지금 중지"라 하면 상태를 바꿉니다. 둘 다 요구되면 둘 다 변경하세요.

## 9. 공유 폴더 · 프린터 (NOS 범위의 File/Print)

## 11. 리눅스 단답형 필수 (후기에 나온 항목)

| 항목 | 핵심 |
|---|---|
| **traceroute vs tracert** | 리눅스 `traceroute`는 기본 **UDP** 패킷, 윈도우 `tracert`는 **ICMP Echo** 사용 (둘 다 **TTL을 1씩 늘려** 경로 파악, 중간 라우터가 **ICMP Time Exceeded(11)** 응답) |
| **netstat** | `netstat -tulnp`(LISTEN 포트), `-antp`(TCP+PID), `-rn`(라우팅) · 후속 `ss` |
| **chmod 755** | `rwxr-xr-x` (소유자 전체, 그룹·기타 읽기+실행) |
| **passwd** | 비밀번호 변경. 계정 정보는 `/etc/passwd`, 암호는 `/etc/shadow` |
| **grub** | 부트 로더. GRUB Legacy 설정 `/boot/grub/grub.conf`, GRUB2는 `/etc/default/grub` 수정 후 `grub2-mkconfig -o /boot/grub2/grub.cfg` |
| **init / 런레벨** | `/etc/inittab`, `init 0`(종료) `init 6`(재부팅) `init 3`(CLI) `init 5`(GUI). 최신은 `systemctl set-default` |
| **/etc/fstab** | 부팅 시 자동 마운트 설정 (장치 · 마운트점 · 파일시스템 · 옵션 · dump · fsck 순서) |
| **ping 응답 설정** | `echo 1 > /proc/sys/net/ipv4/icmp_echo_ignore_all` → ping **무시(차단)**, `0` → 응답 허용. 영구 설정은 `/etc/sysctl.conf`의 `net.ipv4.icmp_echo_ignore_all` |

### ping 출력 읽기 (2026-1회 32번 · 2회 10번)
**리눅스**
```
$ ping -c 3 icqa.or.kr
64 bytes from 210.103.175.224: icmp_seq=1 ttl=54 time=7.45 ms
64 bytes from 210.103.175.224: icmp_seq=2 ttl=54 time=7.17 ms
64 bytes from 210.103.175.224: icmp_seq=3 ttl=54 time=7.08 ms
--- icqa.or.kr ping statistics ---
3 packets transmitted, 3 received, 0% packet loss, time 2002ms
rtt min/avg/max/mdev = 7.085/7.237/7.450/0.155 ms
```
- `-c 3` = **3회** 전송 · `icmp_seq` = 순서 번호 · `ttl` = **남은 홉 수**(초가 아님) · `time` = 왕복 시간(RTT)
- 통계 줄 **`rtt min/avg/max/mdev`** 의 순서는 **최소 / 평균 / 최대 / 표준편차**입니다. 평균은 두 번째 값(7.237), 최대는 세 번째 값(7.450)입니다. (기출 1회 32번: ‘평균 7.450ms’는 틀린 설명)

**윈도우**
```
C:\> ping www.icqa.or.kr
210.103.175.224의 응답: 바이트=32 시간=3ms TTL=55
패킷: 보냄 = 4, 받음 = 4, 손실 = 0 (0% 손실)
왕복 시간(밀리초): 최소 = 2ms, 최대 = 3ms, 평균 = 2ms
```
- 기본 **4회 · 32바이트**(리눅스는 기본 **무한 반복 · 56바이트 데이터**)
- **TTL=55는 ‘55초’가 아니라 남은 홉 수**입니다 (기출 2회 10번 틀린 보기). 윈도우 통계는 최소·최대·**평균** 순서입니다.

### netstat 옵션 (리눅스, 2026-2회 28번)
| 옵션 | 의미 |
|---|---|
| `-a` | **모든 연결 + 수신 대기(LISTEN) 포트** |
| `-t` | **TCP** 연결 (※ ‘연결 후 시간 정보’가 아님 ← 기출 오답 보기) |
| `-u` | UDP |
| `-l` | LISTEN 상태만 |
| `-n` | 주소·포트를 **숫자**로 표시 |
| `-p` | **PID와 프로그램명** |
| `-r` | **라우팅 테이블** |
| `-i` / `-s` | 인터페이스 통계 / 프로토콜별 통계 |

윈도우 `netstat`: `-a`(전체) · `-n`(숫자) · `-o`(**PID**) · `-r`(라우팅) · `-b`(실행 파일) · `-e`(이더넷 통계) · `-s`(프로토콜 통계)

### 리눅스 서버 설치 요약 (NOS 범위의 "Linux Server 설치")
- 설치 방식: 매체(DVD·USB·**네트워크/PXE**), 텍스트/그래픽
- 파티션: 최소 `/`(루트) + `swap`, 서버는 `/boot`, `/home`, `/var` 분리 권장

- 설치 후: root 암호, 일반 계정, 네트워크(IP·호스트명), 방화벽·SELinux, 패키지 업데이트

## 14. 마무리 체크 문제

1. 2급 실기 윈도우 서버 문제의 작업 방식은? → **ICQA 에뮬레이터에서 GUI 조작**
2. DNS에서 영역 종류 중 쓰기 가능한 원본은? → **주 영역(Primary)**
3. SOA의 Refresh·Retry·Expire 의미? → **갱신 확인 주기 / 실패 시 재시도 / 유효 인정 기간**
4. A 레코드와 CNAME의 차이? → **호스트→IP / 별칭→다른 이름**
5. DHCP에서 특정 MAC에 항상 같은 IP를 주는 기능? → **예약(Reservation)**
6. DHCP에서 분배하지 않을 주소 범위? → **제외 범위**
7. 같은 IP로 웹 사이트 2개를 운영하는 방법? → **포트 또는 호스트 이름으로 바인딩 구분**
8. IIS에서 특정 IP 대역 접근을 막는 기능? → **IP 주소 및 도메인 제한(거부 항목)**
9. 사용자 계정 옵션 중 비밀번호가 만료되지 않게 하는 것? → **암호 사용 기간 제한 없음**
10. 3회 실패 시 60분 잠금 정책의 값? → **임계값 3 / 잠금 기간 60**
11. 최소 암호 사용 기간의 의미? → **변경 후 이 기간 동안은 다시 바꿀 수 없음**
12. 서비스를 부팅 때 자동 시작하게 하는 설정? → **시작 유형 = 자동**
13. 공유 권한과 NTFS 권한이 다를 때 적용되는 것? → **더 제한적인 쪽**
