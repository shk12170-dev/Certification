## 1. 계층별 장비 정리 (최빈출 ★★★)

| 계층 | 장비 | 기능 | 판단 기준 |
|---|---|---|---|
| **1 물리** | **리피터(Repeater)** | 신호 증폭·재생 (감쇠 보상) | - |
| **1 물리** | **허브(Hub)** | 다중 포트 리피터. **모든 포트로 플러딩** | - |
| **2 데이터링크** | **브리지(Bridge)** | 세그먼트 연결, MAC 학습, 소프트웨어 방식 | **MAC 주소** |
| **2 데이터링크** | **스위치(Switch)** | 다중 포트 브리지, **하드웨어(ASIC) 처리** | **MAC 주소** |
| **3 네트워크** | **라우터(Router)** | 서로 다른 네트워크 연결, 경로 선택 | **IP 주소** |
| **3 네트워크** | **L3 스위치** | 라우팅 기능 내장 스위치 | IP 주소 |
| **4 전송** | **L4 스위치** | 포트 기반 로드밸런싱 | **포트 번호** |
| **7 응용** | **L7 스위치 / 게이트웨이** | 콘텐츠 기반 분배, 프로토콜 변환 | 패킷 내용 |

### L4 스위치 vs L7 스위치 (2026-3회 46번)
| 구분 | **L4 스위치** | **L7 스위치** |
|---|---|---|
| 동작 계층 | **4계층(전송)** — 네트워크(3) 계층 장비가 아님 | 7계층(응용) |
| 판단 기준 | IP 주소 + **TCP/UDP 포트 번호** | **HTTP 헤더·URL·쿠키** 등 요청 내용 |
| 용도 | 서버 **부하 분산**(로드 밸런싱), 세션 유지 | URL·쿠키 기반 분배, 콘텐츠 라우팅 |

> 기출 46번(복수 정답 ②·③): ‘L4가 네트워크 계층 장비’라는 설명은 **명백히 오답**이고, ‘HTTP 등의 헤더를 분석해 부하 분산’도 L7 성격이라 함께 인정되었습니다. 서버의 부하 분산, 외부 요청이 L4를 거쳐 서버로 분산되는 설명은 맞는 설명입니다.

### 허브 vs 스위치 (출제 단골)
| 구분 | **허브** | **스위치** |
|---|---|---|
| 계층 | 1계층 | 2계층 |
| 동작 | 모든 포트로 **플러딩** | MAC 학습 후 **해당 포트로만** |
| 대역폭 | **공유** (10Mbps를 나눠 씀) | **포트별 독립** |
| 충돌 도메인 | **전체가 1개** | **포트마다 1개** (충돌 없음) |
| 브로드캐스트 도메인 | 1개 | 1개 (VLAN으로 분할 가능) |
| 통신 방식 | 반이중 | **전이중** |
| 보안 | 취약(도청 쉬움) | 상대적으로 안전 |

### 충돌 도메인 / 브로드캐스트 도메인 (★)
| 장비 | 충돌 도메인 분리 | 브로드캐스트 도메인 분리 |
|---|---|---|
| 허브/리피터 | ✗ | ✗ |
| **브리지/스위치** | **○** | ✗ |
| **라우터** | **○** | **○** |

> **브로드캐스트 도메인을 나눌 수 있는 것은 라우터(또는 VLAN)뿐입니다.** 시험 최다 출제.

### 예제
"8포트 스위치 1대와 4포트 허브 1대가 스위치 한 포트에 연결되어 있을 때 충돌 도메인의 수는?"
→ 스위치 포트 8개 = 충돌 도메인 8개, 그중 허브가 연결된 포트는 허브 전체가 하나의 충돌 도메인이므로 총 **8개**. 브로드캐스트 도메인은 **1개**.

## 2. 스위치 동작 원리

### 스위치의 3가지 기능
| 기능 | 설명 |
|---|---|
| **Learning(학습)** | 들어온 프레임의 **출발지 MAC**을 MAC 테이블에 기록 |
| **Flooding(플러딩)** | 목적지 MAC을 모를 때 **들어온 포트를 제외한 모든 포트로** 전송 |
| **Forwarding(전달)** | MAC 테이블에 있으면 해당 포트로만 전송 |
| **Filtering(필터링)** | 같은 포트 내 통신이면 전달하지 않음 |
| **Aging** | 일정 시간(기본 300초) 후 MAC 테이블 항목 삭제 |

### 스위칭 방식 (출제 포인트)
| 방식 | 설명 | 지연 | 오류 검사 |
|---|---|---|---|
| **Store-and-Forward** | 프레임 **전체 수신 후** FCS 검사하고 전달 | 큼 | **함** |
| **Cut-Through** | **목적지 MAC(앞 6바이트)만 읽고** 즉시 전달 | **가장 작음** | 안 함 |
| **Fragment-Free** | 앞 **64바이트**만 확인 후 전달 (충돌 프레임 걸러냄) | 중간 | 부분적 |

## 3. VLAN (Virtual LAN)

물리적 위치와 무관하게 **논리적으로 브로드캐스트 도메인을 분할**하는 기술.

### 장점
- 브로드캐스트 트래픽 감소
- **보안 향상** (VLAN 간 통신은 라우터/L3 스위치 필요)
- 물리적 재배선 없이 논리적 그룹 변경 가능

### VLAN 종류
| 종류 | 기준 |
|---|---|
| **포트 기반(Port-based)** | 스위치 포트별 할당. **가장 일반적** |
| MAC 기반 | MAC 주소별 |
| 프로토콜 기반 | 프로토콜 종류별 |
| 서브넷 기반 | IP 서브넷별 |

### 주요 개념
| 용어 | 설명 |
|---|---|
| **Access Port** | 하나의 VLAN에만 속하는 포트 (단말 연결) |
| **Trunk Port** | **여러 VLAN 트래픽을 함께 전달**하는 포트 (스위치 간 연결) |
| **IEEE 802.1Q** | **VLAN 태깅 표준**. 프레임에 4바이트 태그 삽입 |
| **ISL** | Cisco 전용 VLAN 태깅(구형) |
| **Native VLAN** | 트렁크에서 태그 없이 전달되는 VLAN (기본 VLAN 1) |
| **VTP** | Cisco VLAN 정보 자동 동기화 프로토콜 — 모드 3가지(아래 표) |
| **VLAN ID 범위** | **1 ~ 4094** (12비트) |
| **Inter-VLAN Routing** | VLAN 간 통신. 라우터(Router-on-a-stick) 또는 L3 스위치 |

### VTP(VLAN Trunking Protocol) 모드 3가지 (2026-1회 26번)
| 모드 | 동작 |
|---|---|
| **Server** | VLAN을 **생성·수정·삭제**할 수 있고 정보를 다른 스위치에 **전파** (기본값) |
| **Client** | VLAN을 직접 만들 수 없고 Server의 정보를 **받아서 동기화** |
| **Transparent** | VTP 정보를 **따르지 않고 자체 VLAN만** 사용하며, 받은 광고는 **그대로 전달(중계)** |

> **‘interface mode’라는 VTP 모드는 없습니다** (기출 1회 26번 정답). VTP는 **트렁크 링크**로 VLAN 정보를 광고하며, 같은 **VTP 도메인** 안에서 동작합니다.

## 4. STP (Spanning Tree Protocol)

> ⚠️ **개념 중심으로 학습**: 루프 방지 목적, 포트 상태 4단계 순서, 루트 브리지 선출 기준, RSTP가 더 빠르다는 점만 확실히 하세요. 세부 타이머 수치는 후순위입니다.

스위치를 이중화하면 **루프(Loop)**가 발생 → **브로드캐스트 스톰**, MAC 테이블 불안정
→ **STP(IEEE 802.1D)**가 논리적으로 일부 경로를 차단해 루프를 제거합니다.

### STP 포트 상태 (순서 암기 ★)
```
Blocking(20초) → Listening(15초) → Learning(15초) → Forwarding
                                                    (총 약 50초 수렴)
```
| 상태 | 설명 |
|---|---|
| **Blocking** | 데이터 전달 안 함, BPDU만 수신 |
| **Listening** | BPDU 송수신, MAC 학습 안 함 |
| **Learning** | MAC 학습 시작, 데이터 전달 안 함 |
| **Forwarding** | 정상 데이터 전달 |
| Disabled | 관리자 비활성화 |

### 포트 역할
| 역할 | 설명 |
|---|---|
| **Root Port** | 루트 브리지까지 비용이 가장 낮은 포트 (**루트 브리지에는 없음**) |
| **Designated Port** | 각 세그먼트에서 지정된 전달 포트 |
| **Blocked(Non-Designated) Port** | 차단된 포트 |

### 루트 브리지 선출
**브리지 ID = 우선순위(2바이트, 기본 32768) + MAC 주소(6바이트)**
→ **브리지 ID가 가장 작은 스위치가 루트 브리지**
→ 우선순위가 같으면 **MAC 주소가 가장 작은 쪽**

### STP 개선 버전
| 프로토콜 | 특징 |
|---|---|
| **STP (802.1D)** | 수렴 시간 약 50초 |
| **RSTP (802.1w)** | **Rapid STP** — 수렴 수초 이내 |
| **MSTP (802.1s)** | 여러 VLAN을 인스턴스로 묶어 관리 |
| PVST+ | Cisco, VLAN별 STP |

## 5. 라우터

### 기능
1. **경로 선택(Routing)** — 최적 경로 결정
2. **패킷 전달(Forwarding)** — 결정된 경로로 전송
3. **브로드캐스트 차단** — 브로드캐스트 도메인 분리
4. 서로 다른 네트워크·프로토콜 연결
5. ACL을 통한 필터링, NAT

### 라우팅 테이블 구성 요소
목적지 네트워크 / 서브넷마스크 / 넥스트홉(게이트웨이) / 출력 인터페이스 / **메트릭** / **AD(관리 거리)**

### 관리 거리(AD, Administrative Distance) — 낮을수록 신뢰 ★

> ⚠️ **심화**: '직접 연결 0 < 정적 1 < OSPF 110 < RIP 120' 순서 정도만 알아두면 충분합니다.

| 경로 종류 | AD |
|---|---|
| **직접 연결(Connected)** | **0** |
| **정적 경로(Static)** | **1** |
| EIGRP(내부) | 90 |
| **OSPF** | **110** |
| **RIP** | **120** |
| EIGRP(외부) | 170 |
| BGP(외부) | 20 |
| 알 수 없음 | 255 (사용 불가) |

### 라우팅 프로토콜 비교
| 구분 | RIP | OSPF | EIGRP | BGP |
|---|---|---|---|---|
| 분류 | IGP / 거리벡터 | IGP / **링크상태** | IGP / 하이브리드 | **EGP** / 경로벡터 |
| 메트릭 | **홉 수** | **Cost(대역폭)** | 대역폭·지연 등 | AS 경로·정책 |
| 최대 홉 | **15** | 제한 없음 | 224 | - |
| 갱신 | 30초 주기 전체 | 변경 시만 | 변경 시만 | 변경 시만 |
| 알고리즘 | Bellman-Ford | **Dijkstra(SPF)** | DUAL | Path Vector |
| 규모 | 소규모 | **대규모** | 중·대규모 | 인터넷 백본 |

### RIP의 루프 방지 기법 (출제 포인트)
| 기법 | 설명 |
|---|---|
| **Split Horizon** | 학습한 경로를 **그 경로를 알려준 인터페이스로 다시 광고하지 않음** |
| **Route Poisoning** | 끊어진 경로를 홉 16(무한대)으로 광고 |
| **Poison Reverse** | Split Horizon + 무한대 값으로 되돌려 광고 |
| **Hold-down Timer** | 일정 시간 해당 경로 갱신 무시 |
| **Triggered Update** | 변경 발생 즉시 갱신 전송 |
| **최대 홉 15** | 무한 카운트 방지 |

## 6. 게이트웨이와 기타 장비

| 장비 | 역할 |
|---|---|
| **게이트웨이(Gateway)** | **서로 다른 프로토콜·구조의 네트워크 연결**, 프로토콜 변환 (7계층까지) |
| **기본 게이트웨이** | 외부 네트워크로 나가는 출구 (보통 라우터 IP) |
| **NIC (랜카드)** | 1·2계층, MAC 주소 보유 |
| **모뎀(Modem)** | 디지털 ↔ 아날로그 변환 (Modulation/Demodulation) |
| **CSU/DSU** | 디지털 전용선 접속 장치 |
| **트랜시버** | 신호 송수신 변환 |
| **로드 밸런서** | 트래픽 분산 (L4/L7) |
| **프록시 서버** | 대리 요청, 캐싱, 접근 제어 |
| **방화벽** | 패킷 필터링 |
| **AP (Access Point)** | 무선 ↔ 유선 연결 |
| **무선 컨트롤러(WLC)** | 다수 AP 중앙 관리 |
| **KVM 스위치** | 여러 서버를 하나의 키보드/모니터로 |
| **UPS** | 무정전 전원 장치 |
| **패치 패널** | 케이블 배선 정리 |

### 로드 밸런서(Load Balancer)와 분산 알고리즘 (2026-1회 47번 · 2회 41·49번)
같은 서비스를 제공하는 **여러 서버를 묶어** 요청을 나눠 주는 장비·기술입니다. **상태 확인(Health Check)** 으로 정상 서버에만 요청을 전달해 **장애 내성(고가용성)** 을 높입니다. (L4=포트 기반 / L7=URL·헤더 기반)

| 알고리즘 | 동작 |
|---|---|
| **Round Robin** | 서버에 **순차적으로 돌아가며** 분배 (특별한 규칙 없음). 예: 같은 도메인에 대해 DNS가 서로 다른 IP를 번갈아 응답 |
| Weighted Round Robin | 서버 성능에 따라 **가중치**만큼 더 많이 분배 |
| **Least Connection** | **현재 연결 수가 가장 적은** 서버로 분배 |
| Weighted Least Connection | 연결 수 + 가중치를 함께 고려 |
| IP Hash | 클라이언트 IP를 해시해 **항상 같은 서버**로 (세션 유지) |
| Least Response Time | **응답 시간이 가장 짧은** 서버로 분배 |

## 7. 케이블과 배선

### UTP 케이블 종류 (실기 직결 ★)
| 종류 | 용도 | 배열 |
|---|---|---|
| **다이렉트(Direct / Straight-through)** | **서로 다른 종류** 장비 연결<br>PC↔허브, PC↔스위치, 스위치↔라우터 | 양쪽 끝 **동일** |
| **크로스(Cross-over)** | **같은 종류** 장비 연결<br>PC↔PC, 스위치↔스위치, 라우터↔라우터, PC↔라우터 | 한쪽만 **다르게** |
| **롤오버(Rollover / 콘솔 케이블)** | **PC ↔ 라우터/스위치 콘솔 포트** (설정용) | 완전 역순 |

> ⚠️ **PC ↔ 라우터는 크로스**입니다. 둘 다 "종단 장비"로 분류되기 때문입니다. 함정 문제 단골.
> (최신 장비의 Auto-MDIX 기능으로 실제로는 아무거나 되지만, **시험은 이론 기준**으로 답합니다.)

### T568B 배열 (표준) — 실기 필수 암기
```
1 주백(흰주) 2 주 3 녹백(흰녹) 4 파 5 파백(흰파) 6 녹 7 갈백(흰갈) 8 갈
```

### T568A 배열

## 8. RAID (Redundant Array of Independent Disks)

| 레벨 | 방식 | 최소 디스크 | 가용 용량 | 장애 허용 | 특징 |
|---|---|---|---|---|---|
| **RAID 0** | **스트라이핑** | 2 | 100% | **없음** | 성능 최고, 안정성 최악 |
| **RAID 1** | **미러링** | 2 | **50%** | 1개 | 안정성 높음, 용량 손실 큼 |
| RAID 2 | 해밍코드 ECC | 3 | - | 1개 | 실사용 거의 없음 |
| RAID 3 | 바이트 + 전용 패리티 | 3 | (n-1)/n | 1개 | 패리티 디스크 병목 |
| RAID 4 | 블록 + 전용 패리티 | 3 | (n-1)/n | 1개 | 패리티 디스크 병목 |
| **RAID 5** | 블록 + **분산 패리티** | **3** | (n-1)/n | **1개** | **성능·안정성 균형. 가장 널리 사용** |
| **RAID 6** | **이중 분산 패리티** | **4** | (n-2)/n | **2개** | 안정성 강화 |
| **RAID 10 (1+0)** | 미러 → 스트라이프 | 4 | 50% | 그룹당 1개 | 고성능 + 고안정성 |
| RAID 0+1 | 스트라이프 → 미러 | 4 | 50% | 제한적 | RAID 10보다 복구 취약 |

### 용량 계산 예제
- 1TB 디스크 4개로 RAID 5 → 가용 용량 **3TB** (n-1)
- 1TB 디스크 4개로 RAID 6 → 가용 용량 **2TB** (n-2)
- 1TB 디스크 4개로 RAID 1+0 → 가용 용량 **2TB** (50%)
- 1TB 디스크 4개로 RAID 0 → 가용 용량 **4TB** (장애 허용 0)

### 핫스페어(Hot Spare)
장애 발생 시 자동으로 투입되는 예비 디스크.

## 9. 네트워크 관리 및 감시

### SNMP
| 구성 요소 | 역할 |
|---|---|
| **Manager (NMS)** | 관리 콘솔. 장비에 질의 |
| **Agent** | 관리 대상 장비에 설치된 소프트웨어 |
| **MIB** | 관리 정보를 계층적으로 정의한 데이터베이스 |
| **OID** | MIB 내 객체 식별자 |

| 명령 | 방향 | 설명 |
|---|---|---|
| **GET / GETNEXT / GETBULK** | Manager → Agent | 정보 조회 |
| **SET** | Manager → Agent | 설정 변경 |
| **TRAP** | **Agent → Manager** | 이벤트 **능동 보고** (포트 162) |
| INFORM | Agent → Manager | 확인 응답이 있는 트랩 |

버전: v1(community 평문) / v2c / **v3(인증·암호화)**

### 기타 관리 도구
| 도구 | 용도 |
|---|---|
| **Syslog** | 로그 중앙 수집 (UDP 514) |
| **NetFlow / sFlow** | 트래픽 흐름 분석 |
| **RMON** | 원격 모니터링 |
| **Wireshark / tcpdump** | 패킷 캡처·분석 |
| **Nagios / Zabbix / MRTG** | 네트워크 모니터링 |
| **Ping / Traceroute** | 기본 진단 |

## 10. 장애 처리 절차 (서술형 대비)

```
1. 증상 파악 및 범위 확인 (한 대? 전체?)
2. 물리 계층 확인 — 케이블, 링크 LED, 포트 상태
3. IP 설정 확인 — ipconfig / ifconfig (IP, 마스크, 게이트웨이, DNS)
4. 로컬 확인 — ping 127.0.0.1 (TCP/IP 스택 정상 여부)
5. 자기 IP ping → NIC 확인
6. 게이트웨이 ping → 로컬 네트워크 확인
7. 외부 IP ping (8.8.8.8) → 인터넷 연결 확인
8. 도메인 ping / nslookup → DNS 확인
9. 원인 파악 → 조치 → 결과 검증 → 문서화
```

> **"인터넷은 안 되는데 8.8.8.8 ping은 되는 경우"** → **DNS 문제**
> **"게이트웨이 ping은 되는데 외부는 안 되는 경우"** → 라우터/ISP 또는 라우팅 문제
> **"169.254.x.x가 할당된 경우"** → **DHCP 서버 통신 실패**

## 11. 마무리 체크 문제

1. 허브와 리피터의 동작 계층? → **1계층**
2. 스위치와 브리지의 동작 계층과 판단 기준? → **2계층, MAC 주소**
3. 라우터의 동작 계층과 판단 기준? → **3계층, IP 주소**
4. 브로드캐스트 도메인을 분리할 수 있는 장비는? → **라우터** (또는 VLAN)
5. 8포트 스위치의 충돌 도메인 수와 브로드캐스트 도메인 수? → **8개 / 1개**
6. 스위치가 목적지 MAC을 모를 때 하는 동작? → **플러딩(Flooding)**
7. 지연이 가장 작은 스위칭 방식? → **Cut-Through**
8. 오류 검사를 수행하는 스위칭 방식? → **Store-and-Forward**
9. VLAN 태깅 표준과 VLAN ID 범위? → **IEEE 802.1Q, 1~4094**
10. 여러 VLAN을 함께 전달하는 포트? → **트렁크 포트**
11. STP의 표준 번호와 포트 상태 순서? → **802.1D**, Blocking→Listening→Learning→Forwarding
12. 루트 브리지 선출 기준? → **브리지 ID(우선순위+MAC)가 가장 작은 스위치**
13. STP보다 수렴이 빠른 프로토콜? → **RSTP (802.1w)**
14. 정적 경로와 OSPF, RIP의 AD 값? → **1 / 110 / 120**
15. RIP의 최대 홉 수와 루프 방지 기법 3개? → **15**, Split Horizon / Route Poisoning / Hold-down
16. PC와 스위치를 연결할 때 쓰는 케이블? → **다이렉트**
17. 스위치와 스위치를 연결할 때? → **크로스**
18. **PC와 라우터를 직접 연결할 때?** → **크로스** (함정 주의)
19. 라우터 콘솔 포트 접속용 케이블? → **롤오버(콘솔) 케이블**
20. RAID 5와 RAID 6의 최소 디스크와 장애 허용? → **3개/1개, 4개/2개**
21. 1TB 디스크 5개로 RAID 5 구성 시 가용 용량? → **4TB**
22. SNMP에서 Agent가 능동적으로 보고하는 메시지와 포트? → **TRAP, 162**
23. 8.8.8.8 ping은 되는데 웹사이트 접속이 안 되면? → **DNS 문제**
24. 169.254.x.x가 할당되면 원인은? → **DHCP 서버와 통신 실패**
25. 서로 다른 프로토콜의 네트워크를 연결하는 장비? → **게이트웨이**
