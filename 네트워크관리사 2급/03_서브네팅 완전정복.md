## 2. 핵심 공식 4개

```
① 블록 크기(증가분) = 256 - (해당 옥텟의 마스크 값)     ← "매직 넘버"
② 서브넷 개수       = 2^(빌린 비트 수)
③ 호스트 수         = 2^(남은 호스트 비트 수) - 2
④ 네트워크 주소     = 해당 옥텟 값을 블록 크기로 내림
   브로드캐스트      = 다음 네트워크 주소 - 1
```

## 3. 유형 A — "IP와 프리픽스가 주어졌을 때 네트워크/브로드캐스트 구하기"

### 풀이 4단계 (이 순서대로만 하세요)
```
1) 마스크에서 블록 크기 구하기 → 256 - 마스크값
2) 블록 크기의 배수를 나열
3) 주어진 IP가 속한 구간 찾기
4) 구간 시작 = 네트워크 주소, 구간 끝 = 브로드캐스트
   그 사이 = 사용 가능 호스트
```

### 예제 1 — `192.168.1.100/26`
```
1) /26 → 255.255.255.192 → 블록 = 256 - 192 = 64
2) 배수: 0, 64, 128, 192
3) 100은 64 ~ 127 구간
4) 네트워크 주소   : 192.168.1.64
   브로드캐스트     : 192.168.1.127
   사용 가능 호스트 : 192.168.1.65 ~ 192.168.1.126 (62개)
```

### 예제 2 — `200.1.1.130/27`
```
1) /27 → 224 → 블록 = 256 - 224 = 32
2) 배수: 0, 32, 64, 96, 128, 160, 192, 224
3) 130은 128 ~ 159 구간
4) 네트워크   : 200.1.1.128
   브로드캐스트: 200.1.1.159
   호스트 범위 : 200.1.1.129 ~ 200.1.1.158 (30개)
```

### 예제 3 — `10.10.10.77/28`
```
1) /28 → 240 → 블록 = 16
2) 배수: 0,16,32,48,64,80,...
3) 77은 64 ~ 79 구간
4) 네트워크   : 10.10.10.64
   브로드캐스트: 10.10.10.79
   호스트 범위 : 10.10.10.65 ~ 10.10.10.78 (14개)
```

### 예제 4 — `192.168.5.200/29`
```
1) /29 → 248 → 블록 = 8
2) 배수: 0,8,16,...,192,200,208
3) 200은 정확히 배수 → 200 ~ 207 구간
4) 네트워크   : 192.168.5.200
   브로드캐스트: 192.168.5.207
   호스트 범위 : 192.168.5.201 ~ 192.168.5.206 (6개)
```

### 예제 5 — B클래스 `172.20.130.50/18`
```
1) /18 → 255.255.192.0 → 3번째 옥텟 마스크 192 → 블록 = 256-192 = 64
2) 3옥텟 배수: 0, 64, 128, 192
3) 130은 128 ~ 191 구간
4) 네트워크   : 172.20.128.0
   브로드캐스트: 172.20.191.255
   호스트 범위 : 172.20.128.1 ~ 172.20.191.254
   호스트 수   : 2^14 - 2 = 16,382
```

> **B클래스 요령**: 3번째 옥텟으로 구간을 나누고, 브로드캐스트의 **마지막 옥텟은 255**로 채웁니다.

## 4. 유형 B — "서브넷을 N개로 나누려면?"

### 풀이
```
1) 필요한 서브넷 수 이상이 되는 2의 거듭제곱을 찾음 → 빌릴 비트 수 n
2) 새 프리픽스 = 원래 프리픽스 + n
3) 마스크와 호스트 수를 표 ③에서 확인
```

### 예제 — `192.168.10.0/24`를 **6개** 서브넷으로 나누기
```
1) 2² = 4 < 6,  2³ = 8 ≥ 6  →  3비트 차용
2) /24 + 3 = /27
3) 마스크 255.255.255.224, 블록 32, 서브넷당 호스트 30개

생성되는 8개 서브넷:
  192.168.10.0/27    (0   ~ 31)   호스트 1~30
  192.168.10.32/27   (32  ~ 63)   호스트 33~62
  192.168.10.64/27   (64  ~ 95)
  192.168.10.96/27   (96  ~ 127)
  192.168.10.128/27  (128 ~ 159)
  192.168.10.160/27  (160 ~ 191)
  192.168.10.192/27  (192 ~ 223)
  192.168.10.224/27  (224 ~ 255)
```

### 예제 — `172.16.0.0/16`을 **200개** 서브넷으로
```
2⁷ = 128 < 200,  2⁸ = 256 ≥ 200  →  8비트 차용
/16 + 8 = /24  →  255.255.255.0, 서브넷당 호스트 254개
```

## 5. 유형 C — "호스트가 N개 필요하면?"

### 풀이
```
1) 2^h - 2 ≥ 필요 호스트 수 를 만족하는 최소 h를 찾음
2) 프리픽스 = 32 - h
```

### 예제
| 필요 호스트 | 계산 | 프리픽스 | 마스크 |
|---|---|---|---|
| 2개 | 2²-2=2 | **/30** | 255.255.255.252 |
| 5개 | 2³-2=6 | **/29** | 255.255.255.248 |
| 12개 | 2⁴-2=14 | **/28** | 255.255.255.240 |
| 25개 | 2⁵-2=30 | **/27** | 255.255.255.224 |
| 50개 | 2⁶-2=62 | **/26** | 255.255.255.192 |
| 100개 | 2⁷-2=126 | **/25** | 255.255.255.128 |
| 200개 | 2⁸-2=254 | **/24** | 255.255.255.0 |
| 500개 | 2⁹-2=510 | **/23** | 255.255.254.0 |
| 1000개 | 2¹⁰-2=1022 | **/22** | 255.255.252.0 |

> ⚠️ **함정**: "호스트 130개 필요" → /25는 126개라서 **부족**합니다. **/24**를 써야 합니다.

## 6. VLSM (가변 길이 서브넷 마스크)

> ⚠️ **심화**: 2급 계산 문제는 대부분 '네트워크/브로드캐스트/첫·마지막 호스트 구하기'와 '호스트 수 → 프리픽스'입니다. 이 절은 위 유형이 완벽해진 뒤 여유가 있을 때 학습하세요.

필요한 호스트 수가 다른 네트워크에 **크기가 다른 서브넷**을 할당하는 방법.
**큰 것부터 순서대로 할당**하는 것이 핵심입니다.

### 예제 — `192.168.1.0/24`를 아래 요구대로 분할
| 구간 | 필요 호스트 |
|---|---|
| A | 100 |
| B | 50 |
| C | 25 |
| D | 10 |
| WAN1 | 2 |
| WAN2 | 2 |

**큰 것부터 할당:**

| 구간 | 필요 | 프리픽스 | 할당 서브넷 | 주소 범위 | 브로드캐스트 |
|---|---|---|---|---|---|
| **A** | 100 | /25 (126) | `192.168.1.0/25` | .1 ~ .126 | .127 |
| **B** | 50 | /26 (62) | `192.168.1.128/26` | .129 ~ .190 | .191 |
| **C** | 25 | /27 (30) | `192.168.1.192/27` | .193 ~ .222 | .223 |
| **D** | 10 | /28 (14) | `192.168.1.224/28` | .225 ~ .238 | .239 |
| **WAN1** | 2 | /30 (2) | `192.168.1.240/30` | .241 ~ .242 | .243 |
| **WAN2** | 2 | /30 (2) | `192.168.1.244/30` | .245 ~ .246 | .247 |
| 여유 | - | - | `192.168.1.248/29` 남음 | | |

> **라우터 간 WAN 링크는 항상 /30**을 씁니다(호스트 2개면 충분). 기출 단골입니다.

## 7. 서브넷 요약 (Supernetting / Route Aggregation)

> ⚠️ **심화**: 2급 계산 문제는 대부분 '네트워크/브로드캐스트/첫·마지막 호스트 구하기'와 '호스트 수 → 프리픽스'입니다. 이 절은 위 유형이 완벽해진 뒤 여유가 있을 때 학습하세요.

여러 네트워크를 하나의 큰 네트워크로 묶어 라우팅 테이블을 줄이는 것.

### 예제 — 아래 4개를 요약하면?
```
192.168.0.0/24
192.168.1.0/24
192.168.2.0/24
192.168.3.0/24
```
3번째 옥텟을 2진수로:
```
0 = 000000 00
1 = 000000 01
2 = 000000 10
3 = 000000 11
    └공통 6비트┘
```
공통 비트 = 16(앞 두 옥텟) + 6 = **22**
→ 요약 결과: **`192.168.0.0/22`**

> 요령: **묶는 개수가 2ⁿ개면 프리픽스에서 n을 뺍니다.** (4개 = 2² → /24에서 2를 빼 /22)

## 8. 네트워크 주소를 AND 연산으로 구하기 (원리)

```
IP       192.168.1.100 = 11000000.10101000.00000001.01100100
마스크    255.255.255.192 = 11111111.11111111.11111111.11000000
─────────────────────── AND ───────────────────────────────
네트워크  192.168.1.64  = 11000000.10101000.00000001.01000000
```
> 실제 시험에서는 AND 연산보다 **블록 크기 방법이 훨씬 빠릅니다.** 원리만 알아두세요.

## 8-1. 실기 계산 유형 (윈도우 서버 IP 설정 문제 대비)

실기 윈도우 서버 첫 문제는 **IP 설정**이며, 값을 직접 계산해서 입력하는 경우가 있습니다(후기 기준).

### 유형 ① 2진수 IP → 10진수
```
11000000.10101000.01100100.00001010
= 128+64 . 128+32+8 . 64+32+4 . 8+2
= 192 . 168 . 100 . 10
```
옥텟 비트 가중치: **128 64 32 16 8 4 2 1**

### 유형 ② 프리픽스 → 서브넷 마스크
`/22` → 앞 22비트가 1 → 255.255.**252**.0 (3번째 옥텟의 앞 6비트 = 128+64+32+16+8+4 = 252)

### 유형 ③ 첫 사용 가능 IP / 마지막 사용 가능 IP
```
첫 사용 가능 IP   = 네트워크 주소 + 1
마지막 사용 가능 IP = 브로드캐스트 주소 - 1
```

### 유형 ④ 필요한 호스트 수 → 프리픽스·마스크
호스트 6개 → 2³−2 = 6 → **/29 (255.255.255.248)**

| 29 | `255.255.254.0`의 CIDR와 호스트 수 | /23, 510개 |
| 30 | `192.168.2.0/23`의 주소 범위와 브로드캐스트 | 192.168.2.0 ~ 192.168.3.255 / 192.168.3.255 |

## 10. 시험장 30초 풀이 루틴

```
문제를 보면 ↓
1. 프리픽스 확인 → 마스크의 "마지막 유효 옥텟 값" 확인
2. 블록 = 256 - 그 값        (예: /26 → 256-192 = 64)
3. 블록 배수를 머릿속으로 센다 (0, 64, 128, 192)
4. IP가 낀 구간 찾기
5. 구간 시작 = 네트워크 / 구간 끝 = 브로드캐스트 / 그 사이 = 호스트
```

**이 5단계를 30문제 반복하면 시험장에서 20초 안에 풀립니다.**
계산 실수를 줄이려면 문제지 여백에 **블록 배수를 먼저 적어놓고** 시작하세요.

## 11. 자주 틀리는 포인트

1. **`-2`를 빼먹는 실수** — 호스트 수는 항상 2ⁿ - 2
2. **서브넷 수는 -2 하지 않음** — 최신 장비는 subnet-zero를 사용하므로 2ⁿ 그대로
   (단, 오래된 교재는 서브넷도 -2 하는 경우가 있으니 문제 지문을 확인하세요)
3. **B클래스 브로드캐스트의 마지막 옥텟은 255**
4. **블록 배수에 정확히 걸리는 IP는 그 자체가 네트워크 주소** (예: 192.168.5.200/29)
5. **172.16~172.31만 사설 IP**
6. **WAN 링크는 /30**
