## 1. 데이터 통신의 기본

### 통신 시스템 구성 요소
**송신자 → 송신기 → 전송매체 → 수신기 → 수신자** (+ 프로토콜)

### 프로토콜의 3요소 (출제 단골 ★)
| 요소 | 의미 |
|---|---|
| **구문(Syntax)** | 데이터의 형식, 부호화, 신호 레벨 |
| **의미(Semantics)** | 제어 정보, 오류 처리 방법 |
| **시간(Timing)** | 속도 조절, 순서 제어 |

### 프로토콜의 기본 기능 10가지 (2026-3회 13번)
| 기능 | 설명 |
|---|---|
| **단편화와 재결합** | 큰 데이터를 작은 단위로 나누어 보내고 수신 측에서 다시 합침 |
| **캡슐화(Encapsulation)** | 데이터의 **앞(헤더)·뒤(트레일러)에 주소·오류 검출·제어 정보를 부가**하는 과정 |
| **연결 제어** | 연결 설정 → 데이터 전송 → 연결 해제 (연결형/비연결형) |
| **흐름 제어** | 송신 속도를 수신 측 처리 능력에 맞춰 조절 |
| **오류 제어** | 오류 검출 + 재전송/정정 |
| **동기화(Synchronization)** | 송수신 측의 타이밍·상태를 일치시킴 |
| **순서 결정** | 데이터 단위에 순서를 부여해 재정렬 |
| **주소 지정(Addressing)** | 송·수신 개체를 식별 |
| **다중화(Multiplexing)** | 하나의 회선·연결을 여러 사용자가 공유 |
| **전송 서비스** | 우선순위·서비스 등급(QoS)·보안 제공 |

> 기출 13번: 헤더와 트레일러를 부가하는 과정 = **캡슐화**

### 통신 방식 (전송 방향)
| 방식 | 설명 | 예 |
|---|---|---|
| **단방향(Simplex)** | 한 방향만 | 라디오, TV 방송 |
| **반이중(Half-Duplex)** | 양방향이지만 동시 불가 | 무전기, 허브 환경 |
| **전이중(Full-Duplex)** | 양방향 동시 가능 | 전화, 스위치 환경 |

### 데이터 전송 방식
| 구분 | 설명 |
|---|---|
| **직렬(Serial)** | 한 비트씩 순차 전송. 장거리에 유리 |
| **병렬(Parallel)** | 여러 비트 동시 전송. 단거리 고속 |
| **동기식(Synchronous)** | 블록 단위, 클럭 동기. 고속·효율적 |
| **비동기식(Asynchronous)** | 문자 단위, Start/Stop 비트 사용. 저속 |

### 교환 방식
| 방식 | 설명 |
|---|---|
| **회선 교환(Circuit Switching)** | 전용 경로 설정 후 통신. 전화망. 지연 일정, 자원 독점 |
| **패킷 교환(Packet Switching)** | 패킷 단위 분할 전송. 인터넷 |
| ├ **가상회선(Virtual Circuit)** | 경로 미리 설정, **순서 보장**. X.25, 프레임릴레이, ATM |
| └ **데이터그램(Datagram)** | 패킷마다 독립 경로, **순서 미보장**. IP |
| **메시지 교환** | 전체 메시지 단위 저장 후 전달(Store-and-Forward) |

## 2. OSI 7계층 (최빈출 ★★★)

| 계층 | 이름 | 역할 | PDU | 장비 | 프로토콜 |
|---|---|---|---|---|---|AAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAA
| 7 | **응용(Application)** | 사용자 서비스 제공 | 데이터/메시지 | - | HTTP, FTP, SMTP, DNS, SNMP, Telnet, DHCP |
| 6 | **표현(Presentation)** | 형식 변환·압축·암호화 | 데이터 | - | JPEG, MPEG, ASCII, SSL/TLS |

| 3 | **네트워크(Network)** | **라우팅(경로 선택)**, 논리주소 | **패킷** | **라우터**, L3 스위치 | **IP, ICMP, IGMP, ARP, RARP** |
| 2 | **데이터링크(Data Link)** | 인접 노드 간 오류·흐름 제어, MAC 주소 | **프레임** | **스위치, 브리지**, NIC | Ethernet, PPP, HDLC, LLC/MAC |

### 암기법
- 계층 순서(1→7): **물데네전세표응**
- 장비 계층: **허리(1) - 스브(2) - 라(3)**
- PDU: **비트 - 프레임 - 패킷 - 세그먼트 - 데이터**

|---|---|
| **LLC (Logical Link Control)** | 상위 계층과의 인터페이스, 흐름·오류 제어 (IEEE 802.2) |
| **MAC (Media Access Control)** | 매체 접근 제어, 물리 주소 지정 (IEEE 802.3 등) |

### IEEE 802 표준 (출제 포인트)
| 표준 | 내용 |
|---|---|
| **802.1** | 브리지, **STP**, VLAN(802.1Q) |
| **802.2** | **LLC** |
| **802.3** | **CSMA/CD (이더넷)** |
| 802.4 | 토큰 버스 |
| **802.5** | **토큰 링** |
| 802.11 | **무선 LAN (Wi-Fi)** |
| 802.15 | WPAN (**Bluetooth** = 802.15.1, Zigbee = 802.15.4) |
| 802.16 | **WiMAX** (광대역 무선) |

## 3. TCP/IP 4계층과의 대응

| TCP/IP 4계층 | OSI 대응 | 프로토콜 |````````````````````````````````````````````````````````````````````````````
|---|---|---|
| **응용(Application)** | 5·6·7 | HTTP, FTP, SMTP, DNS, SNMP, Telnet |
| **전송(Transport)** | 4 | TCP, UDP |
| **인터넷(Internet)** | 3 | IP, ICMP, IGMP, ARP, RARP |
| **네트워크 접속(Network Access)** | 1·2 | Ethernet, PPP, ARP |

> 일부 교재는 TCP/IP를 5계층(물리/데이터링크 분리)으로 설명합니다. 시험에서는 보통 **4계층**을 기준으로 출제됩니다.

### 캡슐화(Encapsulation) 과정
```
데이터 → [TCP 헤더 + 데이터] = 세그먼트
       → [IP 헤더 + 세그먼트] = 패킷
       → [이더넷 헤더 + 패킷 + FCS] = 프레임
       → 비트 스트림
```
역방향은 **역캡슐화(Decapsulation)**.

## 4. 네트워크 토폴로지

| 형태 | 구조 | 장점 | 단점 |
|---|---|---|---|
| **버스(Bus)** | 하나의 간선 공유 | 설치 간단, 비용 저렴 | **간선 장애 시 전체 마비**, 충돌 많음 |
| **스타(Star)** | 중앙 장비 중심 | **현재 표준**, 장애 격리 쉬움 | 중앙 장비 고장 시 전체 마비 |
| **링(Ring)** | 원형 연결 | 충돌 없음(토큰) | 한 노드 장애가 전체 영향 |
| **메시(Mesh)** | 모든 노드 상호 연결 | **최고 안정성**, 경로 다중화 | 비용·복잡도 최대 |
| **트리(Tree)** | 계층적 스타 확장 | 확장 용이 | 상위 노드 장애 영향 큼 |

### 메시 토폴로지의 링크 수 공식
**n개 노드 완전 연결 시 링크 수 = n(n-1)/2**
예: 노드 6개 → 6×5/2 = **15개**

## 6. 매체 접근 제어(MAC) 방식

| 방식 | 설명 | 사용처 |
|---|---|---|
| **CSMA/CD** | Carrier Sense Multiple Access with **Collision Detection**. 전송 전 회선 감지 → 충돌 감지 시 임의 시간 후 재전송(Backoff) | **유선 이더넷** (IEEE 802.3) |
| **CSMA/CA** | **Collision Avoidance**. 충돌을 사전에 회피(RTS/CTS). 무선은 충돌 감지가 어려움 | **무선 LAN** (IEEE 802.11) |
| **Token Passing** | 토큰을 가진 노드만 전송 → 충돌 없음 | Token Ring, FDDI |
| **Polling** | 주 노드가 차례로 전송 기회 부여 | 메인프레임 |

> 시험 단골: **유선 = CD(감지), 무선 = CA(회피)**

## 7. 전송 매체

### 유선 매체
| 매체 | 구조 | 최대 거리 | 특징 |
|---|---|---|---|

### 광케이블 비교 (출제 포인트)

### 이더넷 규격 읽는 법
```
10 BASE - T
│    │     └── 매체 (T=Twisted pair, F=Fiber, 2=Thin동축, 5=Thick동축)
│    └──────── 전송 방식 (BASE=베이스밴드, BROAD=브로드밴드)
└───────────── 속도 (Mbps)
```

|---|---|---|---|
| 10BASE5 | 10Mbps | Thick 동축 | 500m |
| 10BASE2 | 10Mbps | Thin 동축 | 185m |
| **10BASE-T** | 10Mbps | UTP Cat3 | 100m |
| **100BASE-TX** | 100Mbps | UTP Cat5 | 100m |
| 100BASE-FX | 100Mbps | 광 MMF | 2km |
| **1000BASE-T** | 1Gbps | UTP Cat5e | 100m |
| 1000BASE-SX | 1Gbps | 광 MMF | 550m |
| 1000BASE-LX | 1Gbps | 광 SMF | 5km |
| **1000BASE-BX** | 1Gbps | 광 — **단일 광섬유 1가닥**으로 송·수신(파장 분할) | 변형별로 상이 |

| 10GBASE-SR | 10Gbps | 광 MMF | 300m |

> 기출 23번: 기가비트 이더넷 규격으로 옳은 것은 **1000BASE-SX와 1000BASE-BX (복수 정답)**. 1000BASE-NX·AX는 **존재하지 않는 규격**입니다.

10BASE 계열에서 **세그먼트 5개, 리피터 4개, 노드 연결 세그먼트 3개**까지 허용

## 8. 오류 제어와 흐름 제어

### 오류 검출 방식
| 방식 | 설명 |
|---|---|
| **패리티 비트(Parity)** | 1의 개수를 짝수/홀수로 맞춤. **1비트 오류만 검출**, 정정 불가 |
| **블록 합 검사** | 행·열 패리티 조합 |
| **체크섬(Checksum)** | 데이터를 더한 값 비교. IP/TCP/UDP 헤더에 사용 |
| **CRC (순환 중복 검사)** | 다항식 나눗셈. **오류 검출률 가장 높음**, 이더넷에서 사용(FCS) |
| **해밍 코드(Hamming)** | **오류 검출 + 정정** 가능 |

### 오류 정정 방식
| 방식 | 설명 |
|---|---|
| **ARQ (자동 반복 요청)** | 오류 발생 시 **재전송 요청** — 후진 오류 정정(BEC) |
| **FEC (전진 오류 수정)** | 수신 측에서 **스스로 정정** — 재전송 없음 |

### ARQ 종류 (출제 포인트)
| 종류 | 설명 |
|---|---|
| **Stop-and-Wait ARQ** | 하나 보내고 ACK 기다림. 단순, 비효율 |
| **Go-Back-N ARQ** | 오류 발생 프레임 **이후 전부 재전송** |
| **Selective-Repeat ARQ** | **오류 난 프레임만** 재전송. 효율 높지만 복잡 |
| Adaptive ARQ | 회선 상태에 따라 블록 크기 조절 |

### 흐름 제어
| 방식 | 설명 |
|---|---|
| **Stop-and-Wait** | 한 프레임씩 확인 |
| **Sliding Window** | **윈도우 크기만큼 연속 전송**. TCP가 사용 |
| **XON/XOFF** | 수신 측 버퍼가 차면 **XOFF(전송 중지)**, 비면 **XON(전송 재개)** 문자를 보내는 **소프트웨어 방식** (비동기 직렬 통신) |
| RTS/CTS | **하드웨어 방식** 흐름 제어 신호선 (RS-232C) |

> 기출 1회 22번: 흐름 제어와 **관련 없는 것은 ‘Loop/Echo’** 입니다. 루프 점검·에코 점검(수신 데이터를 송신 측으로 되돌려 비교)은 **오류 검출 방식**입니다.

### 전송 장애(손상) 종류 (2026-1회 23번)
| 장애 | 설명 | 대책 |
|---|---|---|
| **감쇠(Attenuation)** | 거리가 멀수록 **신호 세기가 약해짐** | 증폭기·리피터 |
| **지연 왜곡 = 위상 왜곡(Phase Distortion)** | 여러 주파수 성분이 **서로 다른 지연 시간으로 도달**해 신호가 일그러짐 | 등화기(Equalizer) |
| **잡음(Noise)** | 열잡음(백색잡음), 상호변조 잡음, **누화(Crosstalk, 인접선 간섭)**, **충격성 잡음(Impulse)** | 차폐(STP), 꼬임쌍선, 접지 |

> 기출 1회 23번: ‘주파수 성분마다 지연 시간이 달라 생기는 왜곡’ = **위상(지연) 왜곡**.

| **802.11ac** | Wi-Fi 5 | 5GHz | 6.9Gbps |
| **802.11ax** | Wi-Fi 6 | 2.4/5GHz | 9.6Gbps |

> 함정: **802.11a가 802.11b보다 나중에 표준화된 것처럼 보이지만 둘은 같은 시기이고, a는 5GHz, b는 2.4GHz**입니다.

### 무선랜 구성 요소
| 용어 | 의미 |
|---|---|
| **AP (Access Point)** | 무선 ↔ 유선 연결 장치 |
| **SSID** | 무선 네트워크 식별자 |
| **BSS** | AP 1개로 구성된 기본 서비스 집합 |
| **ESS** | 여러 BSS를 연결한 확장 서비스 집합 |
| **Ad-hoc** | AP 없이 단말끼리 직접 통신 |
| **Infrastructure** | AP를 통한 통신 |

### 무선 네트워크 유형: Ad hoc · Mesh · 센서 (2026-2회 24번)
| 유형 | 설명 |
|---|---|
| **Ad hoc (MANET)** | AP 없이 단말끼리 **임시로 직접 연결** (블루투스 등) |
| **무선 메시(Wireless Mesh)** | 각 노드가 **자기 데이터 통신의 주체이면서 다른 노드의 트래픽을 릴레이·라우팅**해 주는 구조. 군사 기술에서 민간용으로 전환, 전원만 연결하면 AP 설치가 편하고 **유선 없이 망 확장**이 쉬움 ← 기출 정답 |
| **무선 센서 네트워크(WSN)** | 센서 노드가 환경 정보를 수집·전달하는 저전력 네트워크 (Zigbee 등) |
| SDN · CDN | 무선 구성 방식이 아님 (SDN=제어/데이터 평면 분리, CDN=콘텐츠 캐싱) |

### 무선 보안 (순서 암기)
**WEP(취약, RC4) → WPA(TKIP) → WPA2(AES/CCMP) → WPA3(SAE)**

### 이동통신 / 기타 무선
| 기술 | 설명 |
|---|---|
| **Bluetooth** | IEEE 802.15.1, 근거리 10m, 2.4GHz |
| **Zigbee** | IEEE 802.15.4, 저전력 IoT |
| **NFC** | 10cm 이내 근거리 |
| **RFID** | 무선 인식 태그 |
| **WiMAX** | IEEE 802.16, 광대역 무선 |
| **LTE / 5G** | 이동통신 |

## 10. 네트워크 보안 기초

| 용어 | 설명 |
|---|---|
| **기밀성(Confidentiality)** | 인가된 자만 열람 |
| **무결성(Integrity)** | 데이터가 변조되지 않음 |
| **가용성(Availability)** | 필요할 때 사용 가능 |
| **인증(Authentication)** | 신원 확인 |
| **부인방지(Non-repudiation)** | 행위 부인 불가 |

### 공격 유형
| 공격 | 설명 |
|---|---|
| **스니핑(Sniffing)** | 패킷 도청 (수동적 공격) |
| **스푸핑(Spoofing)** | 주소 위장 (IP/ARP/DNS 스푸핑) |
| **DoS / DDoS** | 서비스 거부 (SYN Flooding, Smurf, Ping of Death) |
| **Man-in-the-Middle** | 중간자 가로채기 |
| **세션 하이재킹** | 인증된 세션 탈취 |
| **SQL Injection** | DB 질의 조작 |

### 암호화 방식
| 구분 | 특징 | 예 |
|---|---|---|
| **대칭키(비밀키)** | 암·복호화 키 **동일**. 빠름, 키 분배 어려움 | DES, **AES**, SEED, ARIA, RC4 |
| **비대칭키(공개키)** | 공개키/개인키 **쌍**. 느림, 키 분배 용이 | **RSA**, ECC, DSA, Diffie-Hellman |
| **해시** | 단방향, 무결성 검증 | **MD5, SHA-1, SHA-256** |

### 보안 장비
| 장비 | 역할 |
|---|---|
| **방화벽(Firewall)** | 패킷 필터링, 접근 제어 |
| **IDS** | 침입 **탐지**(경고만) |
| **IPS** | 침입 **방지**(차단까지) |
| **DMZ** | 외부 공개 서버용 완충 구간 |
| **VPN** | 암호화 터널 |
| **UTM** | 통합 위협 관리 |

## 11. 마무리 체크 문제

1. 프로토콜의 3요소? → **구문, 의미, 시간**
2. OSI 7계층을 1계층부터 순서대로? → 물리-데이터링크-네트워크-전송-세션-표현-응용
3. 라우팅을 담당하는 계층과 PDU? → **3계층 네트워크, 패킷**
4. 스위치와 브리지의 동작 계층? → **2계층**
5. IEEE 802.3과 802.11은 각각? → **CSMA/CD(이더넷) / 무선 LAN**
6. IEEE 802.1의 대표 기술 2가지? → **STP, VLAN(802.1Q)**
7. 노드 8개를 메시로 완전 연결할 때 링크 수? → 8×7/2 = **28**
8. 유선과 무선의 매체 접근 방식? → **CSMA/CD / CSMA/CA**
9. 단일모드 광섬유의 광원과 전송 거리? → **레이저, 수십 km**
10. 100BASE-TX의 속도와 매체? → **100Mbps, UTP Cat5**
11. 오류 검출률이 가장 높은 방식? → **CRC**
12. 오류 검출과 정정을 모두 할 수 있는 코드? → **해밍 코드**
13. 오류 난 프레임만 재전송하는 ARQ? → **Selective-Repeat ARQ**
14. TCP가 사용하는 흐름 제어 방식? → **슬라이딩 윈도우**
15. 802.11a와 802.11g의 주파수? → **5GHz / 2.4GHz**
16. 현재 권장되는 무선 보안 규격? → **WPA2 이상 (AES)**
17. 대칭키와 비대칭키 대표 알고리즘? → **AES / RSA**
18. 침입을 탐지만 하는 장비와 차단까지 하는 장비? → **IDS / IPS**
19. 가상회선과 데이터그램의 차이? → 가상회선은 경로 고정·**순서 보장**, 데이터그램은 독립 경로·순서 미보장
20. 전이중 통신이 가능한 장비는? → **스위치** (허브는 반이중)
