# 두 시험 공통 출제 개념 — 효율 2배 노트

리눅스마스터 2급의 "리눅스 활용(네트워크)"과 네트워크관리사 2급의 "TCP/IP·네트워크 일반·NOS"는 상당 부분 겹칩니다.
**이 문서 하나로 두 시험에서 각각 10~15문항을 커버합니다.**

---

## 1. OSI 7계층 ↔ TCP/IP 4계층 (양쪽 시험 최빈출)

| OSI 계층 | TCP/IP 계층 | 주요 프로토콜 | 전송 단위(PDU) | 장비 |
|---|---|---|---|---|
| 7 응용(Application) | 응용 | HTTP, FTP, SMTP, DNS, SNMP, Telnet, SSH, DHCP | 메시지/데이터 | - |
| 6 표현(Presentation) | 응용 | JPEG, MPEG, ASCII, SSL/TLS | 메시지 | - |
| 5 세션(Session) | 응용 | NetBIOS, RPC, SSH | 메시지 | - |
| 4 전송(Transport) | 전송 | **TCP, UDP** | 세그먼트(TCP) / 데이터그램(UDP) | L4 스위치, 방화벽 |
| 3 네트워크(Network) | 인터넷 | **IP, ICMP, IGMP, ARP, RARP** | 패킷 | **라우터**, L3 스위치 |
| 2 데이터링크(Data Link) | 네트워크 접속 | Ethernet, PPP, HDLC, MAC | 프레임 | **스위치, 브리지**, NIC |
| 1 물리(Physical) | 네트워크 접속 | RS-232, V.35, 10BASE-T | 비트 | **허브, 리피터**, 케이블 |

> ARP/RARP의 소속 계층은 교재마다 2계층 또는 3계층으로 갈립니다. 시험에서는 **"IP 주소 ↔ MAC 주소 변환"이라는 기능**을 묻는 문제가 대부분이므로 기능 중심으로 외우세요.

### 암기법
- 계층 순서(1→7): **물데네전세표응** (물리-데이터링크-네트워크-전송-세션-표현-응용)
- 장비 계층: **허리(1) — 스브(2) — 라(3)** → 허브·리피터=1계층, 스위치·브리지=2계층, 라우터=3계층

### 계층별 역할 한 줄 요약
| 계층 | 역할 |
|---|---|
| 물리 | 비트를 전기/광 신호로 변환, 전송 매체 규격 |
| 데이터링크 | 인접 노드 간 오류제어·흐름제어, MAC 주소 지정, 프레이밍 |
| 네트워크 | **종단 간 경로 선택(라우팅)**, 논리주소(IP) 지정, 단편화 |
| 전송 | 종단 간 신뢰성 있는 데이터 전달, 포트로 프로세스 식별 |
| 세션 | 연결 설정·유지·종료, 동기점(체크포인트) |
| 표현 | 데이터 표현 형식 변환, 압축, 암호화 |
| 응용 | 사용자와 직접 접하는 서비스 제공 |

## 2. 포트 번호 총정리 (양쪽 최빈출)

### 반드시 외울 Well-Known Port
| 포트 | 프로토콜 | 서비스 | 전송 |
|---|---|---|---|
| 20 | FTP-DATA | FTP 데이터 전송 | TCP |
| 21 | FTP | FTP 제어 | TCP |
| 22 | SSH | 보안 원격접속 | TCP |
| 23 | Telnet | 원격접속(평문) | TCP |
| 25 | SMTP | 메일 발신 | TCP |
| 53 | DNS | 도메인 이름 변환 | **TCP/UDP 둘 다** |
| 67 / 68 | DHCP | IP 자동할당 (서버 / 클라이언트) | UDP |
| 69 | TFTP | 간이 파일전송 | UDP |
| 80 | HTTP | 웹 | TCP |
| 110 | POP3 | 메일 수신(다운로드) | TCP |
| 123 | NTP | 시간 동기화 | UDP |
| 137~139 | NetBIOS | 윈도우 파일공유 | TCP/UDP |
| 143 | IMAP | 메일 수신(서버 보관) | TCP |
| 161 / 162 | SNMP / SNMP-TRAP | 네트워크 관리 | UDP |
| 389 | LDAP | 디렉터리 서비스 | TCP |
| 443 | HTTPS | 보안 웹 | TCP |
| 445 | SMB | 윈도우 공유 | TCP |
| 514 | Syslog | 로그 수집 | UDP |
| 3389 | RDP | 윈도우 원격데스크톱 | TCP |

### 포트 범위
- 0 ~ 1023: **Well-Known Port** (예약 포트)
- 1024 ~ 49151: Registered Port (등록 포트)
- 49152 ~ 65535: Dynamic / Private Port (동적 포트)
- 포트 번호는 **16비트** → 0 ~ 65535

### 암기법
20/21/22/23/25가 연속이므로 한 묶음으로: "**20·21 FTP, 22 SSH, 23 Telnet, 25 SMTP**"
메일 3종: 보낼 때 25(SMTP), 받을 때 110(POP3) 또는 143(IMAP).

## 3. TCP vs UDP

| 구분 | TCP | UDP |
|---|---|---|
| 연결 방식 | 연결형(Connection-oriented) | 비연결형(Connectionless) |
| 신뢰성 | 높음 (확인응답·재전송) | 낮음 (확인 없음) |
| 순서 보장 | 보장 | 미보장 |
| 흐름 제어 | 있음 (슬라이딩 윈도우) | 없음 |
| 혼잡 제어 | 있음 | 없음 |
| 헤더 크기 | **20바이트**(최소, 옵션 포함 최대 60) | **8바이트**(고정) |
| 속도 | 상대적으로 느림 | 빠름 |
| 전송 단위 | 세그먼트 | 데이터그램 |
| 용도 | HTTP, FTP, SMTP, Telnet, SSH, POP3 | DNS, DHCP, TFTP, SNMP, NTP, 스트리밍, VoIP |

### TCP 3-Way Handshake (연결 수립)
```
Client                        Server
  │──── SYN ────────────────────▶│   seq = x
  │◀─── SYN + ACK ───────────────│   seq = y, ack = x+1
  │──── ACK ────────────────────▶│   ack = y+1
            연결 수립 완료
```

### TCP 4-Way Handshake (연결 해제)
```
FIN ──▶  ◀── ACK  ◀── FIN  ACK ──▶
```

### TCP 플래그 6종
**URG, ACK, PSH, RST, SYN, FIN**

| 플래그 | 의미 |
|---|---|
| URG | 긴급 데이터 표시 |
| ACK | 확인응답 유효 |
| PSH | 버퍼링 없이 즉시 전달 |
| RST | 연결 강제 재설정/거부 |
| SYN | 연결 요청(동기화) |
| FIN | 연결 종료 요청 |

## 4. IP 주소 체계

### 클래스별 구분
| 클래스 | 첫 옥텟 범위 | 기본 서브넷마스크 | 구조 | 호스트 수 |
|---|---|---|---|---|
| A | 1 ~ 126 | 255.0.0.0 (/8) | N.H.H.H | 16,777,214 |
| B | 128 ~ 191 | 255.255.0.0 (/16) | N.N.H.H | 65,534 |
| C | 192 ~ 223 | 255.255.255.0 (/24) | N.N.N.H | 254 |
| D | 224 ~ 239 | - | 멀티캐스트 전용 | - |
| E | 240 ~ 255 | - | 연구/예약 | - |

> 127로 시작하는 대역은 A클래스 범위에서 빠져 **루프백** 전용입니다.

### 특수 주소 (출제 빈도 높음)
| 주소 | 의미 |
|---|---|
| `127.0.0.0/8` | **루프백**(localhost). 대표 주소 127.0.0.1 |
| `0.0.0.0` | 모든 주소 / 기본 라우트(default route) |
| `255.255.255.255` | 제한적 브로드캐스트 (라우터를 넘지 않음) |
| `169.254.0.0/16` | **APIPA / Link-local** — DHCP 실패 시 자동 할당 |
| `224.0.0.0/4` | 멀티캐스트 |
| 호스트 비트 전부 0 | 네트워크 주소 |
| 호스트 비트 전부 1 | 브로드캐스트 주소 |

### 사설 IP (RFC 1918) — 반드시 암기
| 클래스 | 범위 | CIDR |
|---|---|---|
| A | 10.0.0.0 ~ 10.255.255.255 | 10.0.0.0/8 |
| B | 172.16.0.0 ~ **172.31**.255.255 | 172.16.0.0/12 |
| C | 192.168.0.0 ~ 192.168.255.255 | 192.168.0.0/16 |

> ⚠️ **함정**: `172.32.x.x`는 사설IP가 **아닙니다**(172.16~172.31까지만). 매우 자주 출제됩니다.

## 6. DNS

### 레코드 타입
| 레코드 | 의미 |
|---|---|
| A | 도메인 → IPv4 주소 |
| AAAA | 도메인 → IPv6 주소 |
| CNAME | 별칭(Alias) |
| MX | 메일 서버 (우선순위 값이 **작을수록** 우선) |
| NS | 네임서버 지정 |
| PTR | IP → 도메인 (역방향 조회) |
| SOA | 도메인 권한 시작 정보 (Serial, Refresh, Retry, Expire, TTL) |
| TXT | 텍스트 (SPF, DKIM 등) |

### 질의 방식
- **Recursive Query(재귀적)**: 클라이언트 → 로컬 DNS. 최종 답을 받아올 책임을 떠맡는 방식
- **Iterative Query(반복적)**: 로컬 DNS → 루트 → TLD → 권한 DNS. "나는 모르니 저기 물어봐"

### 계층 구조
```
루트(.) → TLD(.com, .kr) → 2차 도메인(example.com) → 호스트(www)
```

## 7. NAT / 프록시 / 방화벽

- **NAT (Network Address Translation)**: 사설 IP ↔ 공인 IP 변환. IPv4 주소 부족 완화 + 내부망 은닉
  - **Static NAT**: 1:1 고정 매핑
  - **Dynamic NAT**: 주소 풀에서 동적 할당
  - **PAT / NAPT (IP Masquerading)**: 다:1, **포트번호로 구분** — 가정용 공유기 방식
- **프록시(Proxy)**: 클라이언트 대신 요청 수행. 캐싱, 접근제어, 익명성
- **방화벽**: 패킷 필터링(3·4계층) / 애플리케이션 게이트웨이(7계층) / 상태 검사(Stateful)
- **DMZ**: 외부 공개 서버를 두는 완충 구간 (내부망과 분리)
- **IDS**: 침입 탐지(탐지만) / **IPS**: 침입 방지(차단까지)

## 8. 전송 매체 / 케이블 (양쪽 출제)

| 종류 | 최대 거리 | 특징 |
|---|---|---|
| UTP Cat5e | 100m | 1Gbps |
| UTP Cat6 | 100m (10G는 55m) | 10Gbps |
| UTP Cat6a | 100m | 10Gbps |
| STP / FTP | 100m | 차폐(Shield) 있어 노이즈에 강함 |
| 동축(Coaxial) | 185m(10BASE2) / 500m(10BASE5) | Thin / Thick |
| 광 SMF(단일모드) | 수십 km | 장거리, 코어 8~10μm, 레이저 |
| 광 MMF(다중모드) | 2km 이내 | 단거리, 코어 50/62.5μm, LED |

### 이더넷 규격 이름 읽는 법
`10BASE-T` = **10**Mbps / **BASE**band(베이스밴드) / **T**wisted pair
예: `100BASE-TX`, `1000BASE-T`, `1000BASE-SX`, `10GBASE-SR`

### 5-4-3 규칙 (10BASE 계열)
세그먼트 **5**개, 리피터 **4**개, 노드가 붙는 세그먼트 **3**개까지

## 10. 최종 점검 질문 (스스로 답해보기)

1. 라우터는 몇 계층 장비이고 무엇을 보고 전달하는가? → 3계층, IP 주소
2. 스위치는 몇 계층이고 무엇을 보는가? → 2계층, MAC 주소
3. DNS는 TCP인가 UDP인가? → **둘 다** (일반 질의 = UDP 53, 영역 전송 = TCP 53)
4. 172.20.5.1은 사설IP인가? → 예 (172.16~31 범위)
5. 172.40.5.1은? → 아니오, 공인IP
6. DHCP 실패 시 자동 할당되는 대역? → 169.254.x.x (APIPA)
7. `/etc/resolv.conf`의 역할? → DNS 서버 지정
8. IPv6 주소 길이? → 128비트
9. TCP 연결 수립 3단계? → SYN → SYN+ACK → ACK
10. UDP 헤더 크기? → 8바이트 고정
11. MTU 기본값? → 1500바이트
12. 허브와 스위치의 결정적 차이? → 허브는 전체 포트로 플러딩(충돌 도메인 공유), 스위치는 MAC 학습 후 해당 포트로만 전달
