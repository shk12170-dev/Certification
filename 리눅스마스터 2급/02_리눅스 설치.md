# 02. 리눅스 설치

---

## 1. 설치 전 준비

### 하드웨어 정보 확인 항목
CPU 아키텍처(x86/x86_64/ARM), 메모리 용량, 디스크 용량·인터페이스, 그래픽 카드, NIC, 사운드 카드

### 디스크 장치명 규칙 (출제 포인트)

| 인터페이스 | 장치명 | 예 |
|---|---|---|
| IDE (PATA) | `/dev/hd[a-d]` | 1st Master=hda, 1st Slave=hdb, 2nd Master=hdc, 2nd Slave=hdd |
| SCSI / SATA / USB / SAS | `/dev/sd[a-z]` | 첫 디스크=sda, 두 번째=sdb |
| NVMe SSD | `/dev/nvme0n1` | 파티션은 `nvme0n1p1` |
| 가상 디스크(KVM) | `/dev/vda` | |
| 플로피 | `/dev/fd0` | |
| CD-ROM | `/dev/cdrom`, `/dev/sr0` | |

### 파티션 번호 규칙 (MBR)
| 번호 | 종류 |
|---|---|
| 1 ~ 4 | **주 파티션(Primary) 또는 확장 파티션(Extended)** |
| 5 이상 | **논리 파티션(Logical)** — 확장 파티션 안에 생성 |

예: `/dev/sda1` = 첫 SATA 디스크의 첫 주 파티션
`/dev/sda5` = 첫 논리 파티션

### MBR vs GPT
| 구분 | MBR | GPT |
|---|---|---|
| 최대 디스크 용량 | **2TB** | 사실상 무제한(9.4ZB) |
| 파티션 개수 | 주 4개 (확장 사용 시 논리 확장) | 128개 이상 |
| 부팅 방식 | BIOS | **UEFI** |
| 백업 | 없음 | 헤더·테이블 이중 저장 |

## 2. 파티션 분할

### 필수 파티션
| 파티션 | 설명 | 권장 크기 |
|---|---|---|
| `/` (루트) | **반드시 필요**. 최상위 디렉터리 | 최소 10GB 이상 |
| **swap** | 가상 메모리. 파일시스템 아님 | 물리 메모리의 1~2배 (일반적으로 RAM ≤ 2GB면 2배, 그 이상은 1~1.5배) |

### 선택 파티션
| 파티션 | 분리 이유 |
|---|---|
| `/boot` | 커널·부트로더 저장. 예전 BIOS 제약 대응, 200MB~1GB |
| `/boot/efi` | UEFI 부팅 시 필요(FAT32) |
| `/home` | 사용자 데이터 분리 → 재설치 시 데이터 보존 |
| `/var` | 로그·메일·스풀 급증 대비 (서버에서 중요) |
| `/usr` | 응용 프로그램 |
| `/tmp` | 임시 파일 폭주 방지 |

### 파티션 분할의 장점
- 특정 영역이 꽉 차도 시스템 전체가 멈추지 않음
- 백업·복구 단위 분리
- 마운트 옵션(읽기전용, noexec 등)을 영역별로 다르게 적용
- 파일시스템 손상 시 피해 범위 국소화

### LVM (Logical Volume Manager)
```
물리 볼륨(PV) → 볼륨 그룹(VG) → 논리 볼륨(LV)
```
- 파티션 크기를 **서비스 중단 없이 확장** 가능
- 여러 디스크를 묶어 하나의 큰 볼륨으로 사용
- 주요 명령: `pvcreate`, `vgcreate`, `lvcreate`, `lvextend`, `vgdisplay`

## 3. 파일시스템 종류 (출제 빈도 높음)

| 파일시스템 | 특징 |
|---|---|
| **ext2** | 저널링 **없음** |
| **ext3** | ext2 + **저널링(Journaling)** 추가, 최대 파일 2TB |
| **ext4** | ext3 개선. 최대 볼륨 1EB, 최대 파일 16TB, extent 방식, 지연 할당 |
| **XFS** | SGI 개발. 대용량 파일·고성능에 강함. **RHEL 7 이후 기본** |
| **Btrfs** | 스냅샷, 서브볼륨, CoW 지원 |
| **ReiserFS** | 작은 파일 처리에 강함 |
| **JFS** | IBM 개발 |
| **swap** | 스왑 전용 |
| **iso9660** | CD/DVD |
| **vfat / FAT32** | 윈도우 호환 |
| **NTFS** | 윈도우. 리눅스는 ntfs-3g로 지원 |
| **NFS** | 네트워크 파일시스템 (UNIX/Linux 간 공유) |
| **CIFS / SMB** | 윈도우 공유 접속 (Samba) |
| **procfs (/proc)** | 커널·프로세스 정보 제공하는 **가상 파일시스템** |
| **sysfs (/sys)** | 장치·드라이버 정보 가상 파일시스템 |
| **tmpfs** | 메모리 기반 임시 파일시스템 |

### 저널링(Journaling)이란?
파일시스템 변경 내용을 먼저 저널 영역에 기록한 뒤 실제 반영. **비정상 종료 시 빠른 복구**가 가능.
→ **ext2는 저널링 없음 / ext3·ext4·XFS는 저널링 있음** (시험 단골)

## 4. 부트 매니저 (부트로더)

| 부트로더 | 특징 |
|---|---|
| **LILO** (Linux Loader) | 구형. 설정 변경 후 `lilo` 명령 재실행 필요. 설정파일 `/etc/lilo.conf` |
| **GRUB** (Legacy, 0.9x) | 설정파일 `/boot/grub/grub.conf` (또는 menu.lst). 대화형 셸 지원 |
| **GRUB2** | 현재 표준. 설정파일 `/boot/grub2/grub.cfg` — **직접 수정하지 않음** |

### GRUB2 설정 절차 (중요)
```bash
vi /etc/default/grub          # 기본 설정 수정
# 또는 /etc/grub.d/ 스크립트 수정
grub2-mkconfig -o /boot/grub2/grub.cfg   # 설정 파일 생성(RHEL 계열)
update-grub                              # (Debian 계열)
```

### GRUB Legacy 설정 항목
```
default=0          # 기본 부팅 항목 (0부터 시작)
timeout=5          # 대기 시간(초)
title CentOS       # 메뉴 표시 이름
  root (hd0,0)     # /boot 위치 — hd0=첫 디스크, 0=첫 파티션
  kernel /vmlinuz-... ro root=/dev/sda2
  initrd /initramfs-...
```
> ⚠️ GRUB의 디스크·파티션 번호는 **0부터 시작**합니다. `(hd0,0)` = 첫 디스크의 첫 파티션.

### 루트 패스워드 분실 시 복구 (단골 문제)
GRUB 메뉴에서 커널 파라미터에 `single`, `1`, 또는 `init=/bin/bash`를 추가해 단일 사용자 모드로 진입 → `passwd root`

## 5. 부팅 과정 (순서 암기)

```
1. BIOS/UEFI — POST 수행, 부팅 장치 선택
2. MBR/GPT — 부트로더(GRUB) 적재
3. GRUB — 커널(vmlinuz) + initramfs 로드
4. 커널 — 하드웨어 초기화, 루트 파일시스템 마운트
5. init / systemd — PID 1 프로세스 실행
6. 런레벨/타깃에 맞는 서비스 시작
7. 로그인 프롬프트(getty / display manager)
```

### 런레벨 (SysV init) — 반드시 암기
| 런레벨 | 의미 |
|---|---|
| 0 | 시스템 종료(halt) |
| **1** | 단일 사용자 모드(single user) — 복구용 |
| 2 | 다중 사용자 모드, **NFS 미지원** |
| **3** | 다중 사용자 모드, **텍스트 콘솔(CLI)** |
| 4 | 미사용(사용자 정의) |
| **5** | 다중 사용자 모드 + **X 윈도(GUI)** |
| 6 | 재부팅(reboot) |

관련 파일: `/etc/inittab` (기본 런레벨 지정)
관련 명령: `runlevel`, `init 3`, `telinit 5`, `who -r`

### systemd 타깃 (런레벨 대응) — 최신 출제
| 런레벨 | systemd 타깃 |
|---|---|
| 0 | `poweroff.target` |
| 1 | `rescue.target` |
| 3 | `multi-user.target` |
| 5 | `graphical.target` |
| 6 | `reboot.target` |

```bash
systemctl get-default                        # 현재 기본 타깃 확인
systemctl set-default multi-user.target      # 기본 타깃 변경
systemctl isolate graphical.target           # 즉시 타깃 전환
```

### init vs systemd
| 구분 | SysV init | systemd |
|---|---|---|
| PID 1 | `init` | `systemd` |
| 실행 방식 | 스크립트 순차 실행 | **병렬 실행** → 부팅 빠름 |
| 설정 단위 | 런레벨 + `/etc/rc.d/` 스크립트 | **유닛(Unit)** |
| 서비스 제어 | `service httpd start` | `systemctl start httpd` |
| 로그 | `/var/log/messages` | `journalctl` |

### systemd 유닛 종류
`.service`(서비스), `.target`(런레벨 대체), `.socket`, `.mount`, `.timer`(cron 대체), `.device`, `.swap`

## 6. 시스템 종료·재부팅 명령

```bash
shutdown -h now            # 즉시 종료
shutdown -h +10            # 10분 후 종료
shutdown -r now            # 즉시 재부팅
shutdown -c                # 예약된 종료 취소
shutdown -k "메시지"        # 실제 종료 없이 경고만
halt                       # 종료
poweroff                   # 전원 차단
reboot                     # 재부팅
init 0 / init 6            # 런레벨로 종료/재부팅
systemctl poweroff / reboot # systemd 방식
sync                       # 버퍼 내용을 디스크에 기록 (종료 전 권장)
```

| 옵션 | 의미 |
|---|---|
| `-h` | halt (종료) |
| `-r` | reboot (재시작) |
| `-c` | cancel (예약 취소) |
| `-k` | 실제 종료 없이 경고 메시지만 |
| `-f` | 다음 부팅 시 fsck 생략 |
| `-F` | 다음 부팅 시 fsck 강제 수행 |

## 7. 마무리 체크 문제

1. 첫 번째 SATA 디스크의 세 번째 논리 파티션 장치명? → `/dev/sda7` (5,6,7 순서)
2. MBR의 최대 디스크 인식 용량? → **2TB**
3. 반드시 필요한 파티션 2개? → `/` 와 **swap**
4. ext2와 ext3의 결정적 차이? → **저널링 유무**
5. RHEL 7 이후 기본 파일시스템? → **XFS**
6. GRUB2 설정 파일 생성 명령(RHEL)? → `grub2-mkconfig -o /boot/grub2/grub.cfg`
7. GUI를 포함한 다중 사용자 런레벨? → **5**
8. 런레벨 5에 해당하는 systemd 타깃? → `graphical.target`
9. `(hd0,1)`이 의미하는 것? → 첫 번째 디스크의 두 번째 파티션
10. 10분 후 시스템을 종료하는 명령? → `shutdown -h +10`
