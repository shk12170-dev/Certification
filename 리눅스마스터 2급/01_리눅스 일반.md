# 01. 리눅스 일반

> 암기 위주 과목. 배점은 크지 않지만 **틀리면 아까운 문제**들이라 확실히 잡고 갑니다.

---

## 1. 리눅스의 탄생과 역사

| 연도 | 사건 |
|---|---|
| 1969 | **UNIX** 탄생 — AT&T 벨 연구소, 켄 톰슨(Ken Thompson) |
| 1972 | 데니스 리치(Dennis Ritchie)가 **C 언어**로 UNIX 재작성 |
| 1983 | **리처드 스톨만(Richard Stallman)** — GNU 프로젝트 시작 |
| 1985 | FSF(Free Software Foundation) 설립 |
| 1987 | **앤드루 타넨바움** — MINIX 발표 (교육용 UNIX 계열) |
| 1989 | **GPL** 발표 |
| **1991** | **리누스 토발즈(Linus Torvalds)** — 리눅스 커널 0.01 발표 (핀란드 헬싱키 대학) |
| 1992 | 리눅스 커널이 GPL 라이선스 채택 |
| 1994 | 리눅스 커널 1.0 발표 |
| 1996 | 커널 2.0, 마스코트 **턱스(Tux) 펭귄** 등장 |
| 2011 | 커널 3.0 |

### 출제 포인트
- **리눅스 창시자 = 리누스 토발즈 (1991년)**
- **GNU 프로젝트 창시자 = 리처드 스톨만 (1983년)**
- **UNIX 개발자 = 켄 톰슨, 데니스 리치**
- **MINIX 개발자 = 앤드루 타넨바움**
- 리눅스 = **GNU 소프트웨어 + 리눅스 커널** → 정식 명칭 "GNU/Linux"

## 2. 리눅스의 특징

| 특징 | 설명 |
|---|---|
| 다중 사용자(Multi-user) | 여러 사용자가 동시에 시스템 사용 |
| 다중 작업(Multi-tasking) | 여러 프로세스 동시 실행 |
| 다중 처리(Multi-processing) | 여러 CPU 동시 활용 (SMP 지원) |
| 다중 플랫폼 | x86, ARM, PowerPC 등 다양한 아키텍처 |
| 계층적 파일시스템 | 루트(/)를 최상위로 하는 트리 구조 |
| 강력한 네트워킹 | TCP/IP 기본 내장 |
| 우수한 이식성(Portability) | C로 작성되어 이식 용이 |
| 뛰어난 안정성·보안성 | 사용자·그룹 권한 기반 |
| 오픈 소스 | 소스 공개, 무료 사용·수정·배포 |
| 가상 콘솔 | 하나의 모니터에서 여러 개의 가상 화면 |

### 단점
- 공식적인 기술 지원 부재(커뮤니티 의존)
- 상용 소프트웨어 상대적 부족
- 하드웨어 드라이버 지원 지연 가능
- 사용자 학습 곡선

## 3. 라이선스 (매우 중요 — 매 회차 출제)

| 라이선스 | 특징 | 파생물 소스 공개 | 대표 예 |
|---|---|---|---|
| **GPL** (GNU General Public License) | **Copyleft**. 2차 저작물도 반드시 GPL로 공개 | **필수** | 리눅스 커널, GCC |
| **LGPL** (Lesser GPL) | 라이브러리용. 링크만 하면 공개 의무 없음 | 링크 시 불필요 | glibc |
| **BSD** | 매우 자유로움. 저작권 표시만 요구 | 불필요 | FreeBSD, OpenSSH |
| **Apache** | BSD 유사 + 특허권 관련 조항 | 불필요 | Apache HTTP Server |
| **MIT / X11** | 가장 단순·자유 | 불필요 | X 윈도 |
| **MPL** (Mozilla Public License) | 파일 단위 Copyleft | 수정 파일만 | Firefox |

### 핵심 구분
- **Copyleft 있음 = GPL** → 소스 공개 의무. "GPL 코드를 쓴 상용 제품도 소스를 공개해야 하는가?" → **예**
- **Copyleft 없음 = BSD, MIT, Apache** → 상용 제품에 넣고 소스 비공개 가능

### FSF의 자유 소프트웨어 4대 자유
1. 목적에 상관없이 실행할 자유
2. 소스를 연구하고 변경할 자유
3. 복제하고 재배포할 자유
4. 개선된 버전을 배포할 자유

### 오픈 소스 관련 용어
- **FSF**: Free Software Foundation (리처드 스톨만)
- **OSI**: Open Source Initiative — 오픈소스 정의(OSD) 관리
- **Copyleft**: 저작권(Copyright)의 반대 개념, 자유를 강제

## 4. 리눅스 커널 버전 체계

### 구 방식 (2.6 이전)
`주버전.부버전.패치버전` → 예 `2.4.18`
- **부버전이 짝수 = 안정(Stable) 버전** (2.0, 2.2, 2.4)
- **부버전이 홀수 = 개발(Development) 버전** (2.1, 2.3, 2.5)

### 신 방식 (2.6 이후)
짝수/홀수 구분을 사용하지 않고 `주.부.패치[-추가]` 형태로 관리
예: `3.10.0-1160.el7.x86_64`

### 커널 확인 명령
```bash
uname -r          # 커널 버전만
uname -a          # 전체 시스템 정보
cat /proc/version # 커널 + 컴파일러 정보
```

### 출제 포인트
"2.4.18은 안정 버전인가?" → **예** (부버전 4 = 짝수)
"2.5.10은?" → 개발 버전

## 5. 배포판(Distribution)

배포판 = **리눅스 커널 + GNU 유틸리티 + 패키지 관리자 + 설치 프로그램**

### 계열별 분류 (출제 빈도 높음)

| 계열 | 패키지 형식 | 패키지 관리자 | 대표 배포판 |
|---|---|---|---|
| **Red Hat 계열** | `.rpm` | `rpm`, `yum`, `dnf` | RHEL, **CentOS**, **Rocky Linux**, AlmaLinux, Fedora |
| **Debian 계열** | `.deb` | `dpkg`, `apt`, `apt-get` | Debian, **Ubuntu**, Linux Mint, Kali |
| **Slackware 계열** | `.tgz` | `pkgtool` | Slackware, openSUSE(zypper/rpm) |
| **기타** | - | `pacman` / `emerge` | Arch Linux / Gentoo |

> ⚠️ **함정 주의**: openSUSE는 Slackware에서 파생되었지만 **rpm 패키지**를 사용합니다.

### 주요 배포판 특징
| 배포판 | 특징 |
|---|---|
| **Slackware** | 최초의 상용 배포판 계열, 가장 UNIX에 가까움 |
| **Debian** | 커뮤니티 주도, 안정성 최우선, 방대한 패키지 |
| **Red Hat / RHEL** | 상용 기업용, 유료 기술지원 |
| **Fedora** | RHEL의 테스트베드, 최신 기술 선도 |
| **CentOS** | RHEL 소스 기반 무료 클론 (CentOS Stream으로 전환) |
| **Rocky / AlmaLinux** | CentOS 정책 변경 후 등장한 RHEL 호환 무료 배포판 |
| **Ubuntu** | Debian 기반, 데스크톱 친화, LTS 5년 지원 |
| **Kali Linux** | 모의해킹·보안 특화 |
| **Android** | 리눅스 커널 기반 모바일 OS |

> 리눅스마스터 2급 실습 환경으로는 **Rocky Linux** 계열이 자주 언급됩니다. 명령어 예제도 RHEL 계열(`yum`/`dnf`, `systemctl`) 기준으로 외우는 것이 유리합니다.

## 6. 리눅스의 활용 분야

| 분야 | 내용 |
|---|---|
| **서버** | 웹(Apache/Nginx), DB(MySQL/PostgreSQL), 메일, DNS, 파일, 프록시 |
| **임베디드** | 라우터, 셋톱박스, 스마트 TV, IoT, 라즈베리파이 |
| **모바일** | Android, Tizen |
| **클라우드/가상화** | KVM, Xen, Docker, Kubernetes, OpenStack |
| **HPC(고성능 컴퓨팅)** | 슈퍼컴퓨터, 클러스터, **베어울프(Beowulf) 클러스터** |
| **데스크톱** | Ubuntu, Fedora Workstation |

### 클러스터링 3종 (출제 포인트)
| 종류 | 목적 | 예 |
|---|---|---|
| **고계산용 클러스터(HPC)** | 계산 성능 향상 | 베어울프 클러스터 |
| **부하분산 클러스터(LVS)** | 트래픽 분산 | Linux Virtual Server |
| **고가용성 클러스터(HA)** | 무중단 서비스 | 이중화, 페일오버 |

### 가상화 방식
| 방식 | 설명 | 예 |
|---|---|---|
| **전가상화(Full Virtualization)** | 게스트 OS 수정 불필요, 하드웨어 완전 에뮬레이션 | KVM, VMware |
| **반가상화(Para Virtualization)** | 게스트 OS 수정 필요, 성능 우수 | Xen |
| **컨테이너** | 커널 공유, 프로세스 수준 격리, 가볍고 빠름 | Docker, LXC |

## 7. 셸(Shell)과 커널의 관계

```
사용자 → 셸(Shell) → 커널(Kernel) → 하드웨어
```

- **커널**: OS의 핵심. 메모리·프로세스·파일시스템·장치 관리
- **셸**: 사용자 명령을 해석해 커널에 전달하는 **명령어 해석기**
- **유틸리티**: 실제 작업을 수행하는 프로그램들

## 8. 마무리 체크 문제

1. 리눅스 커널 최초 개발자와 연도? → **리누스 토발즈, 1991년**
2. GNU 프로젝트 창시자? → **리처드 스톨만**
3. 2차 저작물의 소스 공개를 강제하는 라이선스? → **GPL**
4. 상용 제품에 포함해도 소스 공개 의무가 없는 라이선스 3개? → BSD, MIT, Apache
5. 커널 2.4.18은 안정 버전인가 개발 버전인가? → **안정(짝수)**
6. `.rpm`을 쓰는 계열과 대표 배포판? → Red Hat 계열, RHEL/CentOS/Rocky/Fedora
7. `.deb`를 쓰는 계열? → Debian 계열, Debian/Ubuntu/Mint
8. 커널 버전을 확인하는 명령? → `uname -r`
9. 게스트 OS 수정이 필요한 가상화 방식? → **반가상화(Xen)**
10. 계산 성능 향상을 목적으로 하는 클러스터? → **고계산용(HPC) / 베어울프**
