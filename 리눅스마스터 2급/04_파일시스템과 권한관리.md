## 1. 리눅스 디렉터리 계층 구조 (FHS) — 암기 필수

```
/
├── bin      기본 실행 명령어 (모든 사용자, ls·cp·mv)
├── boot     커널(vmlinuz), initramfs, 부트로더(GRUB)
├── dev      장치 파일 (sda, tty, null, zero)
├── etc      ★ 시스템 설정 파일 (passwd, fstab, hosts)
├── home     일반 사용자 홈 디렉터리
├── lib      공유 라이브러리, 커널 모듈
├── media    이동식 장치 자동 마운트 지점 (USB, CD)
├── mnt      임시 수동 마운트 지점
├── opt      추가 응용 프로그램 (third-party)
├── proc     ★ 가상 파일시스템 — 커널·프로세스 정보 (메모리 상 존재)
├── root     root 계정의 홈 디렉터리 (/ 와 다름!)
├── run      런타임 데이터 (PID 파일 등)
├── sbin     ★ 관리자용 실행 명령어 (fdisk, ifconfig, shutdown)
├── srv      서비스 데이터
├── sys      가상 파일시스템 — 장치·드라이버 정보
├── tmp      임시 파일 (누구나 쓰기 가능, Sticky Bit 설정됨)
├── usr      사용자 공용 프로그램 (usr/bin, usr/sbin, usr/local)
└── var      ★ 가변 데이터 — 로그(log), 메일(mail), 스풀(spool), 캐시
```

### 시험에 나오는 구분
| 질문 | 답 |
|---|---|
| 시스템 설정 파일이 모인 곳? | `/etc` |
| 로그 파일이 저장되는 곳? | `/var/log` |
| 관리자 전용 명령어 위치? | `/sbin`, `/usr/sbin` |
| 커널이 저장되는 곳? | `/boot` |
| 장치 파일 위치? | `/dev` |
| 메모리에만 존재하는 가상 파일시스템? | `/proc`, `/sys` |
| root의 홈 디렉터리? | `/root` |
| 누구나 쓸 수 있는 임시 디렉터리? | `/tmp` |

### `/proc` 주요 파일
| 파일 | 내용 |
|---|---|
| `/proc/cpuinfo` | CPU 정보 |
| `/proc/meminfo` | 메모리 정보 |
| `/proc/version` | 커널 버전 |
| `/proc/partitions` | 파티션 정보 |
| `/proc/mounts` | 마운트 정보 |
| `/proc/interrupts` | IRQ 정보 |
| `/proc/[PID]/` | 개별 프로세스 정보 |

## 2. 파일 권한(Permission) — 최다 출제 ★★★

### 권한 구조
```
 rwx  rwx  rwx
 │    │    └── other (기타 사용자)
 │    └────── group (그룹)
 └─────────── user  (소유자)
```

| 권한 | 기호 | 8진수 | 파일에서의 의미 | 디렉터리에서의 의미 |
|---|---|---|---|---|
| 읽기 | `r` | **4** | 내용 읽기 | 목록 보기(`ls`) |
| 쓰기 | `w` | **2** | 내용 수정 | 파일 생성/삭제 |
| 실행 | `x` | **1** | 실행 | **진입(`cd`)** |

### 8진수 변환 연습 (반드시 즉답 가능해야 함)
| 8진수 | 기호 | 의미 |
|---|---|---|
| 777 | `rwxrwxrwx` | 모두 모든 권한 |
| **755** | `rwxr-xr-x` | 소유자 전체, 나머지 읽기+실행 (**실행파일·디렉터리 표준**) |
| **644** | `rw-r--r--` | 소유자 읽기쓰기, 나머지 읽기 (**일반 파일 표준**) |
| 700 | `rwx------` | 소유자만 |
| 600 | `rw-------` | 소유자만 읽기쓰기 (SSH 키) |
| 666 | `rw-rw-rw-` | 모두 읽기쓰기 |
| 400 | `r--------` | 소유자 읽기만 |
| 111 | `--x--x--x` | 모두 실행만 |

**변환법**: `rwx` → 4+2+1 = 7, `r-x` → 4+0+1 = 5, `r--` → 4

### chmod — 권한 변경
```bash
# 8진수 방식
chmod 755 file
chmod 644 *.txt
chmod -R 755 dir/        # 하위까지 재귀 적용

# 기호 방식
chmod u+x file           # 소유자에게 실행 권한 추가
chmod g-w file           # 그룹 쓰기 권한 제거
chmod o=r file           # other를 읽기만으로 설정
chmod a+x file           # 모두(all)에게 실행 추가
chmod ug+rw,o-rwx file   # 복합 지정
chmod u+s file           # SetUID 설정
chmod g+s dir            # SetGID 설정
chmod o+t dir            # Sticky Bit 설정
chmod --reference=a b    # a의 권한을 b에 복사
```

| 대상 | 기호 |
|---|---|
| user (소유자) | `u` |
| group (그룹) | `g` |
| other (기타) | `o` |
| all (전체) | `a` |

| 연산자 | 의미 |
|---|---|
| `+` | 권한 추가 |
| `-` | 권한 제거 |
| `=` | 권한 지정(나머지 제거) |

### chown / chgrp — 소유권 변경
```bash
chown user1 file            # 소유자 변경
chown user1:group1 file     # 소유자 + 그룹 변경 ★
chown user1.group1 file     # 동일 (점 표기)
chown :group1 file          # 그룹만 변경
chown -R user1 dir/         # 재귀 적용
chgrp group1 file           # 그룹만 변경
```
> `chown`은 **root만** 실행 가능(일반 사용자는 자기 파일의 소유자를 남에게 넘길 수 없음).

## 3. umask — 기본 권한 마스크

```bash
umask           # 현재 값 확인 (예: 0022)
umask -S        # 기호로 확인
umask 0077      # 값 변경
```

### 계산 방법 (시험 단골)
| 대상 | 기준값 | 계산 |
|---|---|---|
| **파일** | **666** | 666 - umask |
| **디렉터리** | **777** | 777 - umask |

> 파일에 기준값 666을 쓰는 이유: 새로 만든 파일에는 **실행 권한을 기본으로 주지 않기 때문**.

### 예제
| umask | 파일 권한 | 디렉터리 권한 |
|---|---|---|
| 022 | 666-022 = **644** | 777-022 = **755** |
| 002 | **664** | **775** |
| 077 | **600** | **700** |
| 000 | **666** | **777** |
| 027 | **640** | **750** |

- root 기본 umask: **022**
- 일반 사용자 기본 umask: **002** (RHEL 계열, UPG 정책)
- 설정 위치: `/etc/profile`, `/etc/bashrc`, `~/.bashrc`

## 4. 특수 권한 — SetUID / SetGID / Sticky Bit ★★★

| 특수 권한 | 8진수 | 표시 위치 | 의미 |
|---|---|---|---|
| **SetUID** | **4** | user 실행 자리 → `s` | 실행 중 **파일 소유자 권한**으로 동작 |
| **SetGID** | **2** | group 실행 자리 → `s` | 실행 중 **파일 그룹 권한**으로 동작 / 디렉터리에 설정하면 생성 파일이 그 그룹을 상속 |
| **Sticky Bit** | **1** | other 실행 자리 → `t` | 디렉터리 내 파일을 **소유자만 삭제** 가능 |

### 설정 예
```bash
chmod 4755 file      # SetUID  → -rwsr-xr-x
chmod 2755 dir       # SetGID  → drwxr-sr-x
chmod 1777 dir       # Sticky  → drwxrwxrwt
chmod 6755 file      # SetUID + SetGID
chmod u+s file       # 기호 방식 SetUID
chmod o+t dir        # 기호 방식 Sticky
```

### 대표 예시 (시험 단골)
| 대상 | 권한 | 특수 권한 |
|---|---|---|
| `/usr/bin/passwd` | `-rwsr-xr-x` (4755) | **SetUID** — 일반 사용자가 `/etc/shadow`를 수정할 수 있게 함 |
| `/tmp` | `drwxrwxrwt` (1777) | **Sticky Bit** — 아무나 쓸 수 있지만 남의 파일은 못 지움 |
| `/var/tmp` | `drwxrwxrwt` | Sticky Bit |

### 대문자 S / T 의 의미 (함정 문제)
- **소문자 `s`/`t`** = 특수 권한 + 실행 권한(x) 둘 다 있음
- **대문자 `S`/`T`** = 특수 권한만 있고 **실행 권한(x)이 없음** → 실제로는 동작하지 않음

예: `chmod 4655 file` → `-rwSr-xr-x` (실행 권한 없어 SetUID 무효)

### SetUID 파일 검색 (보안 점검)
```bash
find / -perm -4000 -type f         # SetUID
find / -perm -2000 -type f         # SetGID
find / -perm -1000 -type d         # Sticky Bit
find / -perm -6000                 # SetUID + SetGID
```

## 5. inode와 파일 속성

### inode에 저장되는 정보
파일 종류, 권한, 소유자 UID/GID, 크기, 링크 수, 타임스탬프(atime/mtime/ctime), **데이터 블록 위치**

### inode에 저장되지 **않는** 것 (출제 포인트)
**파일 이름** — 파일명은 디렉터리 엔트리에 저장됩니다.

```bash
ls -i file            # inode 번호 확인
df -i                 # 파일시스템별 inode 사용량
stat file             # 상세 속성(3가지 시간 포함)
```

### 확장 속성 — chattr / lsattr
```bash
chattr +i file        # immutable — 삭제·수정 불가 (root도) ★
chattr -i file        # 해제
chattr +a file        # append only — 추가만 가능(로그 보호)
lsattr file           # 속성 확인
```
> `chattr +i`가 걸린 파일은 root도 삭제할 수 없습니다. 시험 단골.

## 6. 마운트와 /etc/fstab

```bash
mount                            # 현재 마운트 목록
mount /dev/sdb1 /mnt/data        # 수동 마운트
mount -t ext4 /dev/sdb1 /data    # 파일시스템 지정
mount -o ro /dev/sdb1 /data      # 읽기 전용
mount -o remount,rw /            # 재마운트
mount -a                         # /etc/fstab 전체 마운트
umount /mnt/data                 # 마운트 해제
umount -l /mnt/data              # lazy umount
```

> 사용 중인 디렉터리는 언마운트되지 않습니다(`device is busy`). `fuser -cu /mnt` 또는 `lsof /mnt`로 사용 중인 프로세스를 확인하세요.

### /etc/fstab 필드 구성 (6개 — 순서 암기)
```
/dev/sda2   /home   ext4   defaults   1   2
   (1)       (2)     (3)     (4)     (5) (6)
```
| 필드 | 이름 | 설명 |
|---|---|---|
| 1 | 장치명 | `/dev/sda2`, `UUID=...`, `LABEL=...` |
| 2 | 마운트 포인트 | `/home` (swap은 `swap` 또는 `none`) |
| 3 | 파일시스템 종류 | ext4, xfs, swap, nfs |
| 4 | 마운트 옵션 | defaults, ro, rw, noexec, nosuid, noauto, usrquota |
| 5 | **dump** | 백업 여부 (0=안함, 1=함) |
| 6 | **fsck 순서** | 0=검사안함, **1=루트(/)**, 2=나머지 |

### 주요 마운트 옵션
| 옵션 | 의미 |
|---|---|
| `defaults` | rw, suid, dev, exec, auto, nouser, async |
| `ro` / `rw` | 읽기전용 / 읽기쓰기 |
| `noexec` | 실행 파일 실행 금지 |
| `nosuid` | SetUID 무시 |
| `noauto` | 부팅 시 자동 마운트 안 함 |
| `user` | 일반 사용자도 마운트 가능 |
| `usrquota` / `grpquota` | 쿼터 사용 |

## 7. 파일시스템 생성·점검

```bash
fdisk -l                    # 파티션 목록
fdisk /dev/sdb              # 파티션 편집(대화형)
  n(new) p(primary) w(write) d(delete) t(type) p(print) q(quit)
parted /dev/sdb             # GPT 지원 파티션 도구
gdisk /dev/sdb              # GPT 전용

mkfs -t ext4 /dev/sdb1      # 파일시스템 생성
mkfs.ext4 /dev/sdb1         # 동일
mkfs.xfs /dev/sdb1          # XFS 생성
mke2fs -j /dev/sdb1         # ext3 생성(-j = 저널)

mkswap /dev/sdb2            # 스왑 영역 생성
swapon /dev/sdb2            # 스왑 활성화
swapoff /dev/sdb2           # 스왑 비활성화
swapon -s                   # 스왑 상태 확인 (= cat /proc/swaps)

fsck /dev/sdb1              # 파일시스템 검사·복구 ★
fsck -y /dev/sdb1           # 모든 질문에 yes
e2fsck -f /dev/sdb1         # ext 계열 강제 검사
xfs_repair /dev/sdb1        # XFS 복구
tune2fs -l /dev/sdb1        # ext 파일시스템 정보 조회
tune2fs -c 30 /dev/sdb1     # 최대 마운트 횟수 설정
dumpe2fs /dev/sdb1          # 상세 정보
blkid                       # UUID·파일시스템 타입 확인 ★
lsblk                       # 블록 장치 트리
```

> ⚠️ **`fsck`는 반드시 언마운트 상태에서 실행**해야 합니다. 마운트된 상태에서 실행하면 파일시스템이 손상될 수 있습니다.

## 8. 디스크 쿼터(Quota)

사용자·그룹별 디스크 사용량을 제한하는 기능.

```bash
# 1. /etc/fstab에 usrquota,grpquota 옵션 추가 후 재마운트
# 2. 쿼터 DB 파일 생성
quotacheck -mcug /home
# 3. 쿼터 활성화
quotaon /home
quotaoff /home
# 4. 사용자별 설정
edquota -u user1            # 편집기로 한도 설정
edquota -g group1           # 그룹 쿼터
edquota -t                  # grace period(유예기간) 설정
edquota -p user1 user2      # user1 설정을 user2에 복사
setquota -u user1 100M 200M 0 0 /home
# 5. 확인
quota -u user1              # 사용자 쿼터 확인
repquota /home              # 전체 보고서 ★
repquota -a                 # 모든 파일시스템
```

### 용어
| 용어 | 의미 |
|---|---|
| **soft limit** | 초과 가능하지만 경고 발생, grace period 동안만 허용 |
| **hard limit** | **절대 초과 불가** |
| **grace period** | soft limit 초과 후 허용되는 기간(기본 7일) |
| **blocks** | 용량 제한 |
| **inodes** | 파일 개수 제한 |

## 9. 마무리 체크 문제

1. `rw-r--r--`를 8진수로? → **644**
2. `755`를 기호로? → `rwxr-xr-x`
3. umask가 022일 때 새 파일·디렉터리 권한? → **644 / 755**
4. umask가 027일 때 새 디렉터리 권한? → **750**
5. `/usr/bin/passwd`에 설정된 특수 권한? → **SetUID (4755)**
6. `/tmp`에 설정된 특수 권한과 이유? → **Sticky Bit**, 남의 파일 삭제 방지
7. `drwxrwxrwT`의 의미? → Sticky Bit 설정 but other 실행 권한 없음
8. inode에 저장되지 않는 정보? → **파일 이름**
9. root도 수정·삭제할 수 없게 만드는 명령? → `chattr +i`
10. `/etc/fstab`의 5번째, 6번째 필드? → **dump 여부 / fsck 순서**
11. `/etc/fstab`에서 루트 파일시스템의 fsck 순서 값? → **1**
12. 파일시스템 UUID를 확인하는 명령? → `blkid`
13. `fsck` 실행 시 주의사항? → **반드시 언마운트 후 실행**
14. 절대 초과할 수 없는 쿼터 한도의 이름? → **hard limit**
15. 쿼터 사용 현황 보고서 명령? → `repquota`
